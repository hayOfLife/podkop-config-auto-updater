# Инструкции для чата и ИИ-ассистента

Эта инструкция одинакова в открытом проекте программы и закрытом проекте конфигурации.

## Перед работой с конфигурацией

1. Прочитай `docs/config-authoring.ru.md` и `docs/config-format.ru.md` полностью.
2. Определи, с каким репозиторием работаешь: программа `podkop-config-auto-updater` открыта, данные `podkop-config-auto-updater-config` закрыты. Перед отправкой реальных данных проверь приватность репозитория по GitHub, а не только по имени.
3. В закрытом репозитории прочитай целевую пару `config/split.json` / `config/split.jsonc` либо старую пару `config/main.json` / `config/main.jsonc`. Сохраняй записи, которые пользователь не просил менять.
4. Используй `examples/main.json` только как пример структуры: все его адреса и реквизиты искусственные. Не добавляй их в рабочую конфигурацию.

## Итоговый результат

- Для двух секций используй `schema_version: 3`, новую осмысленную `revision` и обязательные объекты `main`, `notUnderSanctions`, `settings`. Этот формат требует программы 0.2.0 или новее.
- Храни новый конфиг в `config/split.json` и равнозначном `config/split.jsonc`. Старые `config/main.json` / `config/main.jsonc` остаются в формате 2 для прежних загрузчиков; не заменяй их схемой 3 без отдельного согласования перехода.
- JSON записывается в UTF-8. Начиная с 0.1.3 разрешены комментарии // и /* */ вне строк, но не Markdown-ограждения. Заголовок, который должен отображаться в Podkop, передавай объектом `{"comment": "Название группы"}` внутри массива доменов или подсетей схемы 3. Он одинаково хранится в JSON и JSONC; произвольные комментарии JSONC в интерфейс не переносятся.
- Списки содержат добавляемые строки или объекты `{"value": "точное значение", "delete": true}`. Простое отсутствие записи не удаляет её на роутере.
- Одиночный параметр задаётся строкой. Флаги UCI — `"0"` / `"1"`, не JSON boolean. Одиночное удаление требует точного совпадения `value`.
- В `main` и `notUnderSanctions` разрешены параметры соответствующих секций по справочнику. Общие параметры допускаются только в `settings` и только из перечисленных шести ключей.
- При переносе записи между секциями оставляй точный `delete` в исходной секции и добавление в целевой. Учитывай приоритет `notUnderSanctions` перед `main` и пересечение доменов с общими сетями/CDN.
- Поле «URLTest ссылка для проверки» задаётся одиночной строкой `<секция>.urltest_testing_url`. Сохраняй существующий адрес, если пользователь не попросил его заменить; искусственный адрес из примера в рабочий файл не переноси.
- Для `notUnderSanctions` сверяй правила стран и проверок серверов в закрытом проекте. По принятому правилу доверяй явно указанной провайдером стране; неизвестную страну не допускай в этот пул. Это правило отбора не доказывает доступность сервиса. Контроллер OpenAI проверяет только конкретный запрос через подтверждённый маршрут; не объявляй по нему проверенными Claude, Gemini или весь пул.
- Не добавляй одновременно текстовое и массивное представление одного списка доменов или подсетей.
- Не добавляй настройки DNS, удаление или переключение типа подключения, если этого не было в запросе или согласованном конфиге.
- Не включай в файл токен GitHub, пароль роутера, команды оболочки или настройки самой программы. Расписание, «Выключить ip v6» и «Контролировать доступ к OpenAI» (`openai_check_enabled`) относятся к локальным настройкам программы.
- Не заменяй URLTest ссылкой на OpenAI ради регионального контроля. Пул и тип URLTest остаются в UCI; включённый контроллер управляет только внешним выбором `notUnderSanctions`. Он не меняет `main`, firewall или прокси-порты, не отправляет API-ключ и принимает результат только при доказанном маршруте через нужную группу и узел.

## Проверка и отчёт

1. Проверь JSON и правила справочника, отсутствие конфликтующих добавления/удаления и новых дублей.
2. Проверь, что URLTest каждой управляемой секции после известных операций не остаётся без серверов. Если состояние роутера неизвестно, укажи эту границу проверки.
3. Просмотри diff без публикации учётных данных в сообщениях или журналах.
4. В ответе сообщи путь файла, revision, количество добавлений/удалений и что именно проверено. Не печатай рабочие ссылки серверов целиком.
5. Не утверждай, что файл применён на роутере или VPN работает, если проверялся только JSON или Git-репозиторий.
6. Не запускай сетевую проверку OpenAI под видом «Теста соединения» файла. Не называй произвольный HTTP 401 или 200 успехом контроля; ожидается известный JSON об отсутствующей авторизации. Собственное состояние контроллера находится в RAM, но Podkop может штатно сохранять выбор API в своём файле состояния.

## Открытая и закрытая копии документации

В обоих репозиториях файлы `AGENTS.md`, `docs/config-authoring.ru.md`, `docs/config-format.ru.md` и `examples/main.json` должны быть побайтово одинаковыми. Меняя контракт формата или инструкцию, обновляй обе копии. В открытом репозитории допускаются только искусственные примеры; рабочие серверы остаются в закрытом репозитории.

Для проверки выпуска разрешено читать конкретные созданные сборкой пакеты в `dist/` и `.build/`, хотя эти каталоги и расширения APK/IPK исключены из Git. Это исключение относится только к проверке состава, формата и контрольных сумм артефактов; исходный код анализируй по отслеживаемым файлам.
