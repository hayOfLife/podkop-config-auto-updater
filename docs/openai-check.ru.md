# Контроль доступа к OpenAI

Функция версии **0.2.0** управляет только выбором сервера секции `notUnderSanctions`. Она дополняет отбор стран в конфиге проверкой конкретного запроса OpenAI. Установка и работа на реальном роутере пока не подтверждены.

## Включение и область действия

Галочка **«Контролировать доступ к OpenAI»** включена по умолчанию. Это локальная настройка `openai_check_enabled`, которая не приходит из JSON и не относится к галочкам применения полей. Для автоматической работы одновременно нужна включённая галочка **«Работать»**. После изменения сохраните и примените настройки.

Контроль начинается только при настроенной секции `notUnderSanctions` и работающем Clash API Podkop. Он не создаёт дополнительные прокси-порты, не открывает API наружу, не меняет firewall или mixed inbound. Experimental использует сведения работающего Podkop через его локальный Unix API; стабильный Podkop — адрес из своей конфигурации. В обоих случаях доступность Clash API проверяется до управления группой.

В конфиге Podkop остаётся `proxy_config_type: "urltest"` и прежний список серверов. Контроллер определяет конкретный текущий узел, в том числе вложенный в URLTest, и закрепляет его во внешней группе `notUnderSanctions-out`. Пока контроль включён, дальнейший выбор этой группы выполняет контроллер. Успешная повторная проверка не отправляет команду выбора заново. Группа `main` и её ручной выбор не меняются.

## Что именно проверяется

Роутер выполняет IPv4 GET к фиксированному адресу `https://api.openai.com/v1/models` без API-ключа. Curl не использует прокси из переменных окружения (`--noproxy '*'`); запрос идёт обычным маршрутом Podkop. Токен GitHub используется только для скачивания конфига и в этот запрос не попадает.

Во время запроса контроллер ищет соединение в Clash `/connections`. Для подтверждения нужны одновременно точный случайный исходящий порт этой проверки, фактический локальный IPv4 curl, `api.openai.com`, порт назначения 443 и цепочка с `notUnderSanctions-out` и выбранным узлом. Одна лишь запись домена в конфиге не считается доказательством маршрута.

Если соответствующее соединение не увидено или цепочка не совпала, результат — **«Маршрут проверки не подтверждён»** (`route_unconfirmed`). Такой ответ не подтверждает доступность и не вызывает исключение или выбор другого узла по результату проверки, даже если HTTP-ответ выглядит успешным. Контроллер освобождает временно закреплённый выбор и пытается вернуть прежний вариант группы, соблюдая проверку владения. Это возможно и при слишком коротком соединении, которое API не успел показать; статус сам по себе не доказывает поломку VPN.

Успех — ожидаемый HTTP 401 с корректным JSON OpenAI об отсутствии ключа авторизации, включая проверку типа, кода и известного сообщения ошибки. Произвольный 401, HTML-страница или HTTP 200 успехом не считаются. Такой результат означает, что этот запрос дошёл до обычной проверки авторизации, но не проверяет вход в ChatGPT, подписку, модели, голос, Codex, Claude, Gemini или другие сервисы.

## Когда выбирается другой сервер

Правила ниже применяются только после подтверждения маршрута и сохранения ожидаемого выбора группы:

| Результат | Действие |
| --- | --- |
| Ожидаемый ответ об отсутствии авторизации | Оставить сервер; следующая проверка через 3 минуты |
| Точный код `unsupported_country_region_territory` | Сразу выбрать другой доступный узел; исключить текущий на 1 час |
| Сетевая ошибка | Первые две ошибки подряд на одном узле повторить через 30 секунд; после третьей выбрать другой узел и исключить прежний на 5 минут |
| HTTP 429 | Не переключать; отложить проверку на 10 минут |
| HTTP 5xx | Не переключать; повторить через 3 минуты |
| Неизвестный ответ или ошибка проверки сертификата | Не переключать; повторить через 3 минуты |
| Маршрут не подтверждён | Не исключать узел и не выбирать другой по результату запроса; освободить временный выбор и повторить через 3 минуты |

За один проход выполняются максимум две проверки. Если все узлы временно исключены, остаётся текущий выбор: перехода на `main` или прямое соединение нет. Список в UCI и исходный JSON не редактируются при временном исключении сервера.

Программа не измеряет географию выходного IP. Доступность OpenAI не заменяет проверку других сервисов и не означает, что каждый сервер пула работает. Страна и состав пула определяются правилами владельца конфига.

## Ручной выбор и выключение

Перед первым управлением контроллер запоминает прежний выбор группы в RAM. Если выбор изменён вне программы, текущий проход прекращается без переключения и показывает **«Выбранный узел изменён вне программы. Контроль возобновится позже»**. Следующая проверка назначается через три минуты. Для постоянного ручного выбора выключите контроль OpenAI.

При снятии галочки контроля или **«Работать»** программа пытается вернуть предыдущий выбор только если группа всё ещё находится на её последнем выбранном узле и прежний вариант остаётся доступен в группе. Чужой ручной выбор не перезаписывается. Если Clash API недоступен, возврат может не завершиться; служба может продолжить работу без новых проверок для повторной попытки освобождения группы. Нельзя считать восстановление выполненным только по снятой галочке.

При штатной остановке службы попытка освобождения группы выполняется после остановки daemon. Она ждёт общую блокировку до трёх минут, затем пытается вернуть выбор по тем же условиям. Таймаут блокировки или ошибка восстановления возвращают ошибку: остановка не считается подтверждением возврата прежнего узла.

Во время установки обновления самой программы освобождение пропускается, если команда `software status` подтверждает активную операцию `state: running`, `target: self`, `stage: installing`. Проверяется живое состояние установки, а не только сохранённая строка `running`. Общую блокировку в этот момент держит установщик; новая служба подхватывает сохранённое в RAM состояние контроллера. Если установка оборвалась, новая служба не запустилась или Clash API недоступен, восстановление прежнего выбора не гарантируется.

После перезагрузки роутера сведения о прежнем выборе теряются вместе с RAM. Собственный файл состояния Podkop, в том числе `cache.db`, программа не удаляет, не переносит и напрямую не редактирует. Сам Podkop может штатно сохранять выбранный через API узел в этом файле и восстанавливать его после перезапуска. Поэтому контроллер не обещает отсутствие всех записей на флеш-память или восстановление выбора, сохранённого до перезагрузки.

## Статус и диагностика

В версиях 0.2.0–0.2.1 проверка могла завершаться `io_failed` на сборке OpenWrt, где BusyBox не принимает `sleep 0.2`. Этот случай подтверждён выводом `sleep: invalid number '0.2'` на роутере. Исправление после 0.2.1 сохраняет паузу 200 мс через [штатную функцию ucode](https://ucode.mein.io/module-core.html#sleep), не зависящую от поддержки дробных секунд внешней командой. Ошибка возникала в самой проверке и не подтверждала недоступность OpenAI или неисправность выбранного VPN-сервера.

Под результатом обновления конфига отображаются состояние контроля, время последней проверки и следующей попытки по времени браузера, а также безопасный идентификатор выбранного узла. Чтение статуса каждые 10 секунд не запускает новые запросы к OpenAI.

**«Тест соединения»** по-прежнему проверяет только скачивание и разбор файла конфига. Она не запускает контроль OpenAI и не переключает сервер. Состояние контроля также входит в поле `health` вывода команды чтения статуса, выполняемой в SSH роутера от `root`:

```sh
/usr/libexec/podkop-config-auto-updater/run status
```

Ожидается JSON и код 0; команда не проверяет соединение. При `api_unavailable` проверьте работающий Podkop и его Clash API. `not_configured` означает отсутствие подходящей секции; `no_eligible_nodes` — отсутствие доступного для выбора узла. Ошибки API, выбора и временных файлов показываются без тел HTTP-ответов, адресов прокси и токенов.

`health.json`, `health-state.json`, временные ответы и данные проверки находятся в `/tmp/podkop-config-auto-updater` с ограниченными правами. Предыдущий выбор, таймеры временных исключений и счётчики существуют только до перезагрузки. История проверок не ведётся, содержимое ответов в интерфейс и журнал не выводится.
