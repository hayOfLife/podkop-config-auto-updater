# Формат файла конфигурации

Файл — JSON в UTF-8 размером не более 1 МиБ. [Пример схемы 3](../examples/main.json) и [пример схемы 4](../examples/experimental.json) содержат только искусственные адреса и реквизиты. Формат 3 требует **Podkop config auto updater 0.2.0 или новее**, формат 4 — **0.3.0 или новее**. Форматы 1–3 продолжают приниматься с прежним поведением.

| Поле схемы 3 | Значение |
| --- | --- |
| `schema_version` | Число `3` |
| `revision` | Метка из 1–80 латинских букв, цифр, точек, дефисов или подчёркиваний |
| `main` | Обязательный объект параметров `podkop.main` |
| `notUnderSanctions` | Обязательный объект параметров `podkop.notUnderSanctions`; регистр важен |
| `settings` | Обязательный объект с шестью разрешёнными общими настройками |

Объекты могут быть пустыми. Отсутствующий параметр остаётся без изменений, пустой массив не стирает список. Неизвестные поля верхнего уровня отклоняются. Пустой объект секции сам по себе не создаёт пустую секцию UCI.

## Схема 4: нативные подписки Experimental 0.8.8

Схема 4 предназначена для **Podkop Experimental 0.8.8** с нативным форматом UCI `settings.config_version: "2"`. Это другой номер формата, чем `schema_version` нашего файла. Перед применением программа проверяет установленный UCI-формат; файл не мигрирует стабильный Podkop или старую конфигурацию. Неподходящий формат даёт `experimental_version_required` без записи настроек.

Сохраняются обязательные `revision`, `main`, `notUnderSanctions`, `settings`; `schema_version` равен `4`. Добавляются обязательные объекты `sources`, `members` и необязательный массив `replace_members`. Рабочий вариант хранится в отдельном `config/split_experimental.json` без дублирующей JSONC-копии. Старые `main.json` и `split.json` сохраняются по своим URL.

| Объект | Содержание |
| --- | --- |
| `sources.<id>` | Нативный UCI `config source`: `type: "subscription"`, обязательный HTTPS-адрес `url`, необязательные `label` и `update_interval` |
| `members.<id>` | Нативный UCI `config member`: обязательные `section`, `source`, `role`; необязательные `include`, `exclude`, `via` |
| `replace_members` | Уникальные имена `main` и/или `notUnderSanctions`, состав прежних строк которых нужно заменить |

ID источника или строки содержит от 1 до 64 латинских букв, цифр и `_`, начиная с буквы или `_`. Зарезервированы `settings`, `main`, `notUnderSanctions`, `direct`, `block`; имена всех UCI-секций должны быть различны. Коллизия с секцией другого типа отклоняется с `native_section_collision`.

Источник поддерживает только перечисленные поля. `label` — подпись не длиннее 64 байт UTF-8 без управляющих символов; пустая подпись оставляет автоматическое имя Podkop. `update_interval` — `auto` либо положительная длительность с единицей `m`, `h` или `d`, например `30m`, `12h`, `1d`. Сам Podkop определяет период для `auto` по ответу провайдера либо использует сутки. В каждом из объектов `sources` и `members` допускается не более 128 элементов. Один источник можно использовать в нескольких строках обеих секций.

В строке `section` принимает только `main` / `notUnderSanctions`, `source` ссылается на объявленный или существующий источник, `role` — `server` или `fallback`. `via`, если передан, указывает другой источник для подключения к серверам строки. `include` и `exclude` — массивы не более 256 непустых строк длиной до 128 байт UTF-8 без управляющих символов и точных дублей. При передаче они **заменяют список целиком**; `[]` очищает его, а отсутствие ключа сохраняет прежний список. Это позволяет сужать фильтр без сохранения старых разрешений. Проверка файла проверяет формат ссылок на источники; их существование и заполненность проверяются при применении по итоговому UCI.

`replace_members` — отдельная явная операция замены состава строк правила. Для каждого названного правила в `members` должна быть хотя бы одна новая строка. Старые строки этого правила, чьи ID отсутствуют в новом `members`, удаляются; остальные источники и правила сохраняются. Если старые строки нужно удалить, а автоматические удаления выключены, всё применение отклоняется с `native_membership_delete_disabled`. Защищённые локальными галочками поля и состав правил нельзя заменить частично. Источник или строка, отсутствующие в файле, сами по себе не удаляются; объекты `delete` внутри `sources` / `members` не поддерживаются.

Фильтры соответствуют [правилам Podkop 0.8.8](https://github.com/podkop-net/podkop-experimental/blob/v0.8.8/src/backend/model/model.go#L95-L134): сначала `exclude`, затем OR по `include`. Пустой `include` принимает все имена. Обычное слово ищется в начале слов названия без учёта регистра; флаг, пробел или пунктуация означают поиск буквальной подстроки. Регулярные выражения и шаблоны `*` не выполняются. Регистр дублировать не нужно; кириллица и латиница считаются разными словами. Рабочий список разрешений использует флаги и полные русские/английские названия стран, избегая неоднозначных коротких кодов `US` / `DE`. Для `notUnderSanctions` требуется явный список разрешённых стран, чтобы новый сервер неизвестной страны не попал в пул; исключения «Обход», России, Беларуси, неопределённых и тестовых (`test`, `тест`) выходов применяются раньше. Новое неподтверждённое название остаётся вне пула до проверки. Нефильтрованный fallback обошёл бы этот отбор, поэтому в рабочем файле его не добавляют.

Подписки скачивает **сам Podkop**, а не наша программа. [Парсер 0.8.8](https://github.com/podkop-net/podkop-experimental/blob/v0.8.8/src/backend/subscription/parse.go#L49-L85) принимает URI построчно или их Base64-представление; Xray/sing-box JSON и Clash YAML отклоняются. Проверка нашего файла не скачивает подписки и не доказывает доступность серверов. Поддержку конкретного URI проверяет установленное ядро. Список без подходящих узлов при отсутствии fallback блокирует соответствующий трафик; при ошибке обновления Podkop сохраняет предыдущий список.

В нативном формате правила секций содержат домены, IPv4-подсети, community lists и другие параметры маршрутизации, а серверы приходят через `sources` / `members`. Параметры `connection_type`, `proxy_config_type`, `urltest_proxy_links` и прежние секционные параметры URLTest в этом файле не задаются. Пять параметров URLTest находятся в `settings`; подробнее ниже. [Полный искусственный пример](../examples/experimental.json) показывает обе секции и фильтры.

Состояние нашего загрузчика остаётся в RAM. Нативный Podkop отдельно хранит последние списки подписок в `/usr/share/podkop/subscriptions` на flash, чтобы запускаться без сети; программа не переносит и не удаляет этот кэш.

## Параметры секций

В `main` и `notUnderSanctions` разрешены имена параметров Podkop: от 1 до 64 строчных латинских букв, цифр или подчёркиваний, начиная с буквы. Максимум 256 параметров в объекте. Служебные ключи UCI вроде `.type` запрещены. Обе секции имеют тип UCI `section`; совпадение имени с существующей секцией другого типа отклоняет применение. В схемах 1–3 произвольные другие секции конфиг не изменяет; схема 4 дополнительно управляет явно названными `sources` / `members`.

- Строка заменяет одиночный параметр: `"urltest_check_interval": "5m"`. Флаги UCI записываются строками `"0"` и `"1"`.
- Массив строк дополняет список: `"community_lists": ["telegram", "google_play"]`.
- Объект `{"value": "старое значение", "delete": true}` удаляет одиночный параметр только при точном совпадении текущего значения.
- Такой же объект внутри массива удаляет запись списка. Отсутствующая запись не является ошибкой.
- Изменение типа существующего обычного параметра со строки на список или обратно отклоняется. Формат неизвестных параметров сверяйте с установленным Podkop.

Каждый массив содержит не более 10 000 элементов. Добавление и удаление одного нормализованного значения внутри одного списка конфликтуют и отклоняют файл целиком. Удаление строки из файла не удаляет её на роутере: нужен явный `delete`. При выключенных удалениях обычные удаления пропускаются; исключение для переноса между секциями описано ниже.

Три основных списка проверяются дополнительно:

| Ключ внутри секции | Формат |
| --- | --- |
| `urltest_proxy_links` | Отдельные URI VLESS, SS, Trojan, SOCKS4/5, Hysteria2; URL подписки и полный Xray JSON не подходят |
| `user_domains` | Домены без протокола, пути и `*.`; международные имена в punycode |
| `user_subnets` | IPv4 CIDR или одиночные IPv4-адреса в рабочем конфиге |

**Рабочие пары `config/main.json` / `main.jsonc`, `config/split.json` / `split.jsonc` и файл `config/split_experimental.json` содержат только IPv4 в пользовательских подсетях. IPv6 туда не добавляйте:** это правило рабочего конфига и совместимости с формой Podkop 0.7.23. Техническая поддержка IPv6 парсером загрузчика не означает совместимость формы Podkop. Это ограничение списка не отключает IPv6 на роутере.

Вместо массива `user_domains` или `user_subnets` можно указать строку `user_domains_text` или `user_subnets_text`: её адреса добавляются к существующим. Одновременное указание обеих форм одного списка запрещено. Для точечных удалений и заголовков групп используйте массив.

## Заголовки групп в полях Podkop

В схемах 3/4 массивы `user_domains` и `user_subnets` принимают элемент с единственным ключом `comment`:

```json
{
  "schema_version": 3,
  "revision": "headings-demo-1",
  "main": {
    "user_domain_list_type": "text",
    "user_domains": [
      {"comment": "Демонстрационный сервис: сайт и API"},
      "example.com",
      "api.example.net"
    ],
    "user_subnet_list_type": "text",
    "user_subnets": [
      {"comment": "Демонстрационные IPv4-сети сервиса"},
      "192.0.2.0/24"
    ]
  },
  "notUnderSanctions": {},
  "settings": {}
}
```

В текстовом поле Podkop это отображается так:

```text
// Демонстрационный сервис: сайт и API
example.com
api.example.net
```

Заголовок относится к следующим добавляемым записям до нового заголовка. Он не является доменом, подсетью или операцией удаления. Строка не должна состоять только из пробелов, быть длиннее 512 байт или содержать управляющие символы, включая переводы строк; принятый текст сохраняется буквально. Заголовок в конце массива или перед одними удалениями не создаёт строку без адресов. В прокси, community lists и других параметрах такие объекты запрещены.

Подписи групп поддержаны в текстовых полях самого [Podkop 0.7.24](https://github.com/itdoginfo/podkop/blob/0.7.24/luci-app-podkop/htdocs/luci-static/resources/view/podkop/section.js#L487) и [Experimental 0.8.1](https://github.com/podkop-net/podkop-experimental/blob/v0.8.1/src/backend/plan/lists.go#L350): `//` удаляется перед построением правил маршрутизации. Изменять пакет Podkop для этого не требуется. Если текущий список динамический, конфиг должен явно задавать соответствующий `user_domain_list_type` или `user_subnet_list_type` равным `"text"`; иначе применение с заголовками отклоняется с `comments_require_text`. Разрешите также применение этого параметра в локальных галочках программы.

При явном переходе из динамического списка в текстовый загрузчик объединяет активные записи с существующим текстом без новых дублей. Ручные записи и комментарии сохраняются, кроме явно удаляемых адресов. Заголовки из конфига добавляются без повторного размножения при следующем обновлении. Если адресов не осталось, поле становится пустым, без комментариев без адресов.

## Порядок секций и перенос записей

При применении схемы 3 или 4 `notUnderSanctions` располагается перед `main`, если обе секции существуют после объединения. Взаимный порядок прочих секций сохраняется. Форматы 1 и 2 порядок не меняют. Обе секции и общие настройки записываются одной транзакцией; изменение только порядка тоже требует перезапуска. Схема 4 включает в эту транзакцию источники и строки правил. При отсутствии изменений перезапуска нет.

Для переноса укажите точное удаление в исходной секции и добавление в целевой:

```json
{
  "schema_version": 3,
  "revision": "move-demo-1",
  "main": {
    "user_domains": [{"value": "api.example.net", "delete": true}]
  },
  "notUnderSanctions": {
    "user_domains": ["api.example.net"]
  },
  "settings": {}
}
```

Это фрагмент для уже настроенных секций; для создания новой Proxy/URLTest-секции добавьте её тип подключения и реальные серверы. [Полный искусственный пример](../examples/main.json) показывает структуру, но не предоставляет работающий VPN.

Перенос записей основных списков и `community_lists` не выполняется наполовину: если запись ещё есть в исходной секции, а удаление или применение одного из участвующих полей запрещено, всё применение останавливается с `section_move_blocked`. В схемах 1–3 целевая секция после объединения должна быть Proxy/URLTest с непустым пулом; в схеме 4 — включённым правилом с подходящими нативными строками. Переносимая запись должна присутствовать в её активном списке. При невыполнении этих условий перенос также отклоняется. Включите нужные галочки или скорректируйте файл. На чистой установке, где исходной записи уже нет, запрет удаления сам по себе не мешает добавлению. Удаления из исходной секции нужно оставлять в файле для роутеров, которые ещё не перешли на новый конфиг.

Приоритет не означает точного разделения общих сетей: домен из `main`, размещённый в IPv4-сети `notUnderSanctions`, также может пойти через `notUnderSanctions`. Community lists могут пересекаться и меняться независимо от файла. Широкие сети CDN нельзя описывать как адреса только одного сервиса.

## Ссылка для проверки URLTest

Поле **«URLTest ссылка для проверки»** задаётся строкой `<секция>.urltest_testing_url` в схемах 1–3. Пример: `"https://check.example.com/generate_204"` — искусственный адрес, не предназначенный для реального теста. Значение применяется при `proxy_config_type: "urltest"`; серверы перечисляются отдельно в `urltest_proxy_links`. В схеме 4 адрес общий для всех правил и находится в `settings.urltest_testing_url`, серверы приходят через нативные источники и строки.

Переданная строка заменяет текущее значение; отсутствие ключа сохраняет его; объект удаления требует точного совпадения. Не меняйте имеющийся адрес без задачи пользователя.

Обычный URLTest измеряет доступность соединения и задержку. Он не проверяет поддерживаемую страну, вход в аккаунт или работоспособность AI-сервиса. В [ядре Experimental 0.8.1](https://github.com/podkop-net/sing-box/blob/1d47804dc783/common/urltest/urltest.go#L126) HEAD-ответ не проверяется по HTTP-статусу: ответ 403 может дать успешный результат. Замена адреса теста на OpenAI сама по себе не решает региональное ограничение. Для `notUnderSanctions` нужен отдельно отобранный пул; правила доверия указанной провайдером стране определяет владелец конфига, неизвестную страну в этот пул не включают.

Начиная с 0.2.0 локальный флаг «Контролировать доступ к OpenAI» включает отдельную проверку через секцию `notUnderSanctions`. В схемах 1–3 в UCI сохраняются `proxy_config_type: "urltest"`, список серверов и ссылка URLTest; в схеме 4 сохраняются нативные источники, строки и глобальные параметры проверки. Контроллер управляет внешней группой выбора, фиксирует конкретный узел и при необходимости выбирает другой. Он не меняет `main` и не проверяет географию IP. Для принятия результата нужны подтверждённый маршрут запроса в Clash API и ожидаемый JSON OpenAI об отсутствующей авторизации либо распознанная ошибка; произвольный HTTP 401 или 200 не считается успехом. [Подробный алгоритм](https://github.com/hayOfLife/podkop-config-auto-updater/blob/main/docs/openai-check.ru.md).

## DNS и загрузка списков

В схемах 1–3 разрешены только следующие ключи внутри `settings`:

| Поле интерфейса Podkop | Ключ | Значения |
| --- | --- | --- |
| Тип протокола DNS | `dns_type` | `udp`, `doh`, `dot` |
| DNS-сервер | `dns_server` | IP или домен, необязательные порт и путь; без `https://` |
| Bootstrap DNS-сервер | `bootstrap_dns_server` | Адрес в формате Podkop |
| Скачивать списки через Proxy/VPN | `download_lists_via_proxy` | `"0"` или `"1"` |
| Частота обновления списков | `update_interval` | `1h`, `3h`, `12h`, `1d`, `3d` |
| Скачивать списки через выбранную секцию | `download_lists_via_proxy_section` | Имя существующей Proxy/VPN-секции, например `main` или `notUnderSanctions` |

Секция скачивания проверяется после объединения: в схемах 1–3 она должна существовать и иметь тип Proxy/VPN. Частота обновления списков **Podkop** отличается от расписания загрузки этого JSON нашей программой. Токен, расписание, галочки «Работать», «Контролировать доступ к OpenAI» (`openai_check_enabled`) и отключение IPv6 не входят в загружаемый файл.

Схема 4 сохраняет эти шесть полей и допускает также:

| Ключ | Значение |
| --- | --- |
| `config_version` | Только строка `"2"`; отсутствие не отменяет проверку уже установленного нативного формата |
| `urltest_check_interval` | Положительная длительность с единицей `s`, `m`, `h`, `d`, например `3m` |
| `urltest_tolerance` | Допустимая разница задержек, строка целого числа от 0 до 60000 |
| `urltest_testing_url` | Полный HTTP/HTTPS-адрес проверки |
| `urltest_download_check` | `default`, `off` или `custom` |
| `urltest_download_url` | HTTP/HTTPS-адрес пользовательской проверки загрузки при `custom` |

В нативном формате секция скачивания должна иметь подходящие строки `members`; `connection_type: "proxy"` для неё не задаётся. Период `sources.<id>.update_interval` управляет получением подписки самим Podkop и отличается как от общих списков Podkop, так и от расписания нашего JSON.

## Объединение и проверки

- Прокси сравниваются по полной строке. Смена имени после `#` считается другой записью.
- Домены сравниваются без учёта регистра и завершающей точки.
- Подсети сравниваются в каноническом виде: `192.0.2.9/24` соответствует `192.0.2.0/24`, одиночный IPv4 — `/32`.
- Существующие записи сохраняются; новые дубли не добавляются, старые ручные дубли специально не чистятся.
- Явные удаления убирают совпадения также из скрытого представления доменного или адресного списка. Остальные скрытые записи сохраняются.
- Заполненная VPN-, selector- или outbound-секция автоматически не преобразуется. Proxy/URL можно перевести в URLTest с сохранением имеющейся ссылки.
- В схемах 1–3 операция, оставляющая управляемый URLTest без серверов, отклоняется. Схема 4 проверяет состав строк и ссылки на заполненные источники; состав скачанной подписки и подходящие серверы определяет сам Podkop.
- Весь файл проверяется до применения, даже если отдельные поля выключены. Неизвестные общие настройки, неверные типы и повреждённый JSON отклоняют его целиком.

Произвольные имена параметров внутри управляемых секций нужны для совместимости с новыми версиями Podkop. Загрузчик не знает все смысловые ограничения этих полей; поддержку конкретного транспорта проверяет само ядро Podkop.

`revision` — метка результата, не механизм запрета старых версий. Повторная загрузка снова объединяет данные. Вручную удалённая добавляемая запись вернётся при следующем обновлении; восстановленная запись с `delete` снова будет удалена при разрешённых удалениях.

## Комментарии JSONC и совместимость

Начиная с программы 0.1.3 разрешены `// до конца строки` и `/* многострочный комментарий */` вне JSON-строк. Они предназначены для чтения исходного файла и не переносятся автоматически в Podkop. Для заголовков в интерфейсе используйте `{"comment": "Название"}` схемы 3. Эти элементы являются частью данных и должны присутствовать в обеих копиях JSON/JSONC.

URL со знаком `//`, экранированные кавычки и обратные слеши внутри строк сохраняются буквально. Незакрытые комментарии отклоняются. Не используйте завершающие запятые: обычный JSON должен разбираться стандартными инструментами. Расширение файла не меняет правила разбора; лимит 1 МиБ включает комментарии.

| Схема | Программа | Содержание |
| --- | --- | --- |
| 1 | 0.1.0+ | `section: "main"`, `revision` и три массива на верхнем уровне; только основные списки |
| 2 | 0.1.0+ | `schema_version: 2`, `revision`, объекты `main` и `settings`; без второй секции и элементов `comment` |
| 3 | 0.2.0+ | Две секции, их порядок, заголовки в полях Podkop и защита переносов |
| 4 | 0.3.0+ | Нативные подписки `sources` / `members` только для Experimental 0.8.8 с UCI-форматом 2 |

Для схемы 2 с комментариями JSONC нужна программа 0.1.3+. Старые `config/main.json` / `config/main.jsonc` сохранены в схеме 2; новые `config/split.json` / `config/split.jsonc` используют схему 3. Сначала обновите программу до 0.2.0, затем смените ссылку на `split.json` или `split.jsonc`, сохраните её, выполните «Тест соединения» и только затем «Обновить сейчас». Возврат ссылки к `main.json` не удаляет вторую секцию и не отменяет миграцию автоматически.

Для схемы 4 сначала установите программу 0.3.0 и Podkop Experimental 0.8.8 с нативным UCI-форматом, затем укажите отдельный `config/split_experimental.json`. «Тест соединения» проверяет только наш JSON. При переходе с ручных прокси используйте явный `replace_members`, чтобы прежние нефильтрованные строки не расширили новый пул. Возврат к старому URL сам по себе не удаляет источники и строки нативного формата.

## Индивидуальное применение параметров

В списке «Какие настройки применять из конфига» каждый параметр представлен одной галочкой, включённой по умолчанию. Один многозначный список — одна галочка. Снятая галочка сохраняет локальное значение и запрещает его добавления, замены и удаления из файла. После изменения нажмите «Сохранить и применить».

Поля сгруппированы под заголовками **«Секция MAIN»**, **«Секция notUnderSanctions»** и **«Общие настройки Podkop»**. Дополнительные имена берутся из последнего успешно проверенного файла; для их появления выполните «Тест соединения» и обновите страницу. Неизвестное поле показывается с именем секции и по умолчанию разрешено. Текстовая и массивная формы доменов/подсетей управляются одной галочкой в каждой секции.

Локальные запреты хранятся в UCI-списке `ignored_options` загрузчика, например `main.user_domains`, `notUnderSanctions.user_domains` или `settings.dns_server`. Удалённый конфиг не может включить снятую галочку. Запреты обеих секций независимы; связанные переносы проверяются дополнительно. Если операция требует изменить запрещённый тип списка или подключения, всё применение отклоняется с `protected_option_required`.

В схеме 4 параметры источников защищаются ключами `sources.<id>.<параметр>`, строки — `members.<id>.<параметр>`, а замена состава — `membership.main` / `membership.notUnderSanctions`. Список фильтров представлен одной галочкой на `include` или `exclude`; число строк внутри него не создаёт отдельных настроек. Защита действует и при сужении фильтров, и при `replace_members`.

«Тест соединения» проверяет скачивание и формат; настройки Podkop и расписание не меняет. Он не проверяет фактическое применение, выбранный прокси или регион и не запускает контроль OpenAI. После проверки в RAM сохраняются только имена найденных параметров (`/tmp/podkop-config-auto-updater/fields.json`), без их значений и секретов. После перезагрузки дополнительные поля появятся при следующем чтении файла; сохранённые запреты остаются.
