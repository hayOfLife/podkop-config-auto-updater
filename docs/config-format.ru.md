# Формат файла конфигурации

Файл — JSON в UTF-8 размером не более 1 МиБ. [Пример](../examples/main.json) содержит только демонстрационные домены и подсети. Рекомендуемый формат — версия 2 с блоками `main` и `settings`. Отсутствующий параметр остаётся без изменений, пустой массив не стирает список.

| Поле | Значение |
| --- | --- |
| `schema_version` | Число `2` |
| `revision` | Метка из 1–80 латинских букв, цифр, точек, дефисов или подчёркиваний |
| `main` | Объект с параметрами секции `podkop.main` |
| `settings` | Объект с шестью разрешёнными общими настройками; допустим пустой объект |

## Параметры MAIN

В `main` можно передавать любые имена параметров Podkop: от 1 до 64 строчных латинских букв, цифр или подчёркиваний, начиная с буквы. Максимум 256 параметров. Служебные поля UCI вроде `.type` запрещены. Другие секции конфиг менять не может.

- Строковое значение заменяет одиночный параметр: `"urltest_check_interval": "5m"`. Флаги UCI записываются строками `"0"` и `"1"`.
- Массив строк дополняет список: `"community_lists": ["telegram", "google_play"]`.
- Объект `{"value": "старое значение", "delete": true}` удаляет одиночный параметр, только если его текущее значение совпадает.
- Такой же объект внутри массива удаляет одну запись списка. Если удаление выключено в интерфейсе, оно пропускается для всех параметров.
- Изменение типа уже существующего параметра со строки на список или обратно отклоняется. Формат неизвестных параметров нужно сверять с установленным Podkop.

Для трёх основных списков действуют дополнительные правила:

| Ключ в `main` | Формат |
| --- | --- |
| `urltest_proxy_links` | Массив отдельных ссылок VLESS, SS, Trojan, SOCKS4/5, Hysteria2 |
| `user_domains` | Массив доменов без протокола и пути, международные имена в punycode |
| `user_subnets` | Массив IPv4/IPv6, CIDR или одиночных IP |

Вместо `user_domains` или `user_subnets` можно указать строку `user_domains_text` или `user_subnets_text`: её записи будут добавлены к существующим. Одновременное указание обоих представлений одного списка запрещено. Для точечных удалений используйте массив.

## Ссылка для проверки URLTest

Поле **«URLTest ссылка для проверки»** в Podkop соответствует `main.urltest_testing_url`. Это одиночная строка с полным HTTP/HTTPS-адресом, по которому Sing-box проверяет соединение через серверы URLTest. Поле используется при `proxy_config_type: "urltest"`; его имя подтверждено [исходниками Podkop](https://github.com/itdoginfo/podkop/blob/main/luci-app-podkop/htdocs/luci-static/resources/view/podkop/section.js).

Искусственный пример изменения только этого поля:

```json
{
  "schema_version": 2,
  "revision": "urltest-example-1",
  "main": {
    "urltest_testing_url": "https://check.example.com/generate_204"
  },
  "settings": {}
}
```

Демонстрационный адрес не предназначен для реальных проверок. В рабочем файле укажите выбранный адрес проверки. Переданная строка заменяет текущее значение, отсутствие ключа сохраняет его, а `{"value": "точный прежний адрес", "delete": true}` удаляет параметр при совпадении и включённых удалениях. Ссылки самих прокси задаются отдельным массивом `urltest_proxy_links`. Поддержка поля уже есть в версии программы 0.1.0 через обычные параметры MAIN.

## DNS и загрузка списков

Разрешены только следующие ключи внутри `settings`:

| Поле интерфейса Podkop | Ключ | Значения |
| --- | --- | --- |
| Тип протокола DNS | `dns_type` | `udp`, `doh`, `dot` |
| DNS-сервер | `dns_server` | IP или домен, необязательные порт и путь; без `https://` |
| Bootstrap DNS-сервер | `bootstrap_dns_server` | Адрес в формате Podkop |
| Скачивать списки через Proxy/VPN | `download_lists_via_proxy` | `"0"` или `"1"` |
| Частота обновления списков | `update_interval` | `1h`, `3h`, `12h`, `1d`, `3d` |
| Скачивать списки через выбранную секцию | `download_lists_via_proxy_section` | Имя существующей секции Proxy/VPN, например `main` |

Пример явного изменения DNS и скачивания списков через `main`:

```json
{
  "schema_version": 2,
  "revision": "dns-example-1",
  "main": {},
  "settings": {
    "dns_type": "doh",
    "dns_server": "dns.adguard-dns.com/dns-query",
    "bootstrap_dns_server": "77.88.8.8",
    "download_lists_via_proxy": "1",
    "download_lists_via_proxy_section": "main",
    "update_interval": "1d"
  }
}
```

Это пример, а не автоматически выбранные настройки. Частота обновления списков **Podkop** отличается от расписания загрузки конфига нашей программы. Секция скачивания проверяется после объединения: она должна существовать и иметь тип Proxy/VPN. Изменения `main` и `settings` сохраняются одной транзакцией и требуют одного перезапуска Podkop.

Каждый массив содержит не более 10 000 операций. Строка добавляет значение. Объект из двух полей `{"value": "example.com", "delete": true}` удаляет значение, если включена соответствующая галочка. Удаление отсутствующей записи ничего не меняет. При выключенной галочке удаления пропускаются, добавления выполняются.

Удаление строки из самого файла не удаляет её с роутера: нужен явный `delete`. Добавление и удаление одного нормализованного значения в одном списке отклоняет весь файл. Неизвестные поля верхнего уровня, запрещённые общие настройки, неверные типы и повреждённый JSON также отклоняют файл целиком. Произвольные ключи внутри `main` разрешены для совместимости с новыми версиями Podkop; загрузчик не знает все их смысловые ограничения.

## Объединение

- Прокси сравниваются по полной строке. Смена имени после `#` считается другой строкой. URL подписки и полный Xray JSON не подходят.
- Домены сравниваются без учёта регистра и завершающей точки.
- Подсети сравниваются в каноническом виде: `192.0.2.9/24` соответствует `192.0.2.0/24`, одиночный IPv4 — `/32`, IPv6 — `/128`.
- Уже существующие записи сохраняются. Новые дубли не добавляются; старые ручные дубли специально не чистятся.
- Активное текстовое или динамическое представление списка сохраняется. При изменении текстовый список записывается по одному значению на строку, его комментарии и оформление не сохраняются. Без изменений текст остаётся исходным.
- Удаления также убирают совпадение из скрытого представления списка. Остальные скрытые записи остаются на месте.
- Заполненная секция VPN, selector или outbound автоматически не преобразуется. Секция Proxy/URL может быть переведена в URLTest с сохранением существующей ссылки.
- Операция, оставляющая URLTest без единого сервера, отклоняется.

Остальные секции и порядок секций программа не меняет. Значения URLTest, community lists и разрешённые общие настройки меняются только при явном указании в файле. Поддержка протокола конкретным ядром Sing-box и корректность параметров учётной записи проверяются самим Podkop: загрузчик проверяет структуру и тип URI, но не осуществляет подключение к каждому серверу.

`revision` служит меткой результата, а не номером для запрета старых версий. Повторная загрузка того же файла снова выполняет объединение. Поэтому вручную удалённая добавляемая запись вернётся при следующем обновлении, а вручную восстановленная запись с `delete` снова будет удалена.

## Совместимость с первым форматом

Версия `schema_version: 1` продолжает приниматься: обязательны `section: "main"`, `revision` и три массива `urltest_proxy_links`, `user_domains`, `user_subnets` на верхнем уровне. Она меняет только эти списки и необходимые параметры их включения. Для остальных параметров используйте версию 2.

## Комментарии (начиная с 0.1.3)

Разрешены комментарии `// до конца строки` и `/* многострочный комментарий */` вне JSON-строк. Подписывайте заголовком группу доменов или подсетей; не каждую запись. URL со знаком `//`, экранированные кавычки и обратные слеши внутри строк сохраняются буквально. Незакрытые комментарии и завершающие запятые отклоняются. Комментарии не становятся настройками UCI и не отображаются в списках Podkop. Лимит 1 МиБ включает комментарии.

```jsonc
{
  "schema_version": 2,
  "revision": "commented-demo-1",
  "main": {
    "user_domains": [
      // Демонстрационный сервис: сайт и API
      "example.com",
      "api.example.net"
    ],
    "user_subnets": [
      // Демонстрационные сети сервиса
      "192.0.2.0/24",
      "2001:db8::/32"
    ]
  },
  "settings": {}
}
```

Расширение `.jsonc` удобно для редакторов; загрузчик определяет содержимое независимо от расширения. Версии до 0.1.3 принимают только JSON без комментариев. Пока такие роутеры используются, сохраняйте `config/main.json` без комментариев и одинаковый по данным `config/main.jsonc` с заголовками; при изменении обновляйте обе копии. Переключать ссылку на `.jsonc` можно после обновления программы до 0.1.3.
