# Как подготовить итоговый конфиг в чате

Документ предназначен для человека или ИИ-ассистента, которому поручили обновить файл для **Podkop config auto updater**. Итог — один проверенный JSON-файл `config/main.json` в закрытом репозитории с конфигурацией. Применение на роутере — отдельная операция загрузчика.

## Источники и порядок работы

1. Прочитайте задачу пользователя и существующий рабочий файл. Уточняйте только отсутствующие данные, без которых нельзя безопасно выполнить требуемое изменение.
2. Сверьтесь с [точным справочником формата](config-format.ru.md). Имена UCI берите из установленной версии Podkop; не переводите имена ключей на русский язык.
3. Сохраняйте существующие элементы и настройки, которые не относятся к запросу. Если пользователь дал подписку, извлеките из неё отдельные поддерживаемые URI; сам URL подписки не заменяет список URLTest.
4. Подготовьте добавления и явные удаления. Не придумывайте реальные серверы, пароли, токены, адреса DNS или отсутствующие пожелания пользователя.
5. Обновите `revision`, проверьте структуру, сравните изменения и сохраните файл.

## Как выглядит итоговый файл

Файл использует `schema_version: 2` и содержит четыре ключа верхнего уровня:

- `schema_version` — число `2`;
- `revision` — понятная метка изменения, например `2026-10-22-02`;
- `main` — параметры секции `podkop.main`;
- `settings` — разрешённые общие параметры Podkop либо пустой объект.

Полный [искусственный пример](../examples/main.json) показывает три основных списка, ссылку и параметры проверки URLTest, дополнительный список MAIN, точечные удаления и все шесть общих настроек. В примере используются зарезервированные адреса `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` и домены `example.com` / `example.net`. URI, идентификаторы и реквизиты вымышленные. Пример показывает синтаксис и **не предоставляет работающий VPN, DNS или адрес проверки URLTest**.

Поле **«URLTest ссылка для проверки»** задаётся строкой `main.urltest_testing_url`, например `"https://check.example.com/generate_204"` в искусственном примере. Это адрес, по которому Sing-box проверяет соединение через серверы URLTest. Он относится к секции `main`; список самих прокси хранится отдельно в `main.urltest_proxy_links`. При подготовке рабочего файла сохраняйте имеющийся адрес или используйте адрес, указанный пользователем. [Подробные правила](config-format.ru.md#ссылка-для-проверки-urltest).

## Добавление и удаление

Строка в массиве добавляет элемент без нового дубля. Объект с `delete: true` внутри массива удаляет именно `value`. Удалённая из файла строка продолжает существовать на роутере, поэтому для удаления нужна явная операция.

Если операция удаления должна оставаться действующей на всех роутерах, сохраняйте её в конфиге, пока они не обновились. Последующее удаление самой операции из файла не вернёт запись на роутер. Чтобы вернуть запись, замените операцию обычной строкой.

Обычная строка в одиночном параметре заменяет значение. Объект `{"value": "старое значение", "delete": true}` удаляет параметр только при точном совпадении текущего значения. Когда галочка автоматических удалений выключена, все удаления пропускаются; добавления и обычные замены продолжают выполняться.

Нельзя одновременно добавлять и удалять одну запись в одном списке. Пустой массив ничего не очищает. Флаги Podkop записываются строками `"0"` и `"1"`; JSON boolean используется только для `delete: true`.

## Общие настройки

Блок `settings` может содержать только:

| Настройка | Ключ |
| --- | --- |
| Тип протокола DNS | `dns_type` |
| DNS-сервер | `dns_server` |
| Bootstrap DNS-сервер | `bootstrap_dns_server` |
| Скачивать списки через Proxy/VPN | `download_lists_via_proxy` |
| Частота обновления списков | `update_interval` |
| Скачивать списки через выбранную секцию | `download_lists_via_proxy_section` |

Допустимые значения находятся в [справочнике](config-format.ru.md#dns-и-загрузка-списков). Пустой `settings` сохраняет все текущие общие настройки. Частота обновления списков Podkop не задаёт время загрузки этого JSON: расписание 03:00–03:30 и галочка «Выключить ip v6» сохраняются локально в программе и в этот файл не включаются.

## Проверка перед сохранением

- JSON должен разбираться штатным парсером без вывода его содержимого в журнал. Проверка синтаксиса не подтверждает правильность реквизитов серверов.
- Сверьте имена и типы ключей, ограничения размера и количества операций.
- Сравните полный diff: новые записи должны соответствовать запросу, удаляемые — иметь явную пометку, посторонние параметры — сохраниться.
- Учтите сравнение доменов без регистра, канонический вид подсетей и точное сравнение полных proxy URI.
- Проверьте, что указанная секция для скачивания существует и является Proxy/VPN. Если её состояние недоступно, не объявляйте эту проверку выполненной.
- Не допускайте попадания рабочих данных в открытый репозиторий или искусственный пример. Токен GitHub не входит даже в закрытый JSON.

В конце сообщите имя файла, revision, краткий состав изменений и границы проверки. Для передачи текста в чат используйте искусственные значения или сокращённый отчёт, если публикация полных рабочих ссылок не запрошена прямо.
