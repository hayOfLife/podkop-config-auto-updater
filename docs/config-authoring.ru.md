# Как подготовить итоговый конфиг в чате

Инструкция для человека или ИИ-ассистента, которому поручено обновить данные **Podkop config auto updater**. Для двух секций со списками серверов итогом служит пара `config/split.json` / `config/split.jsonc`. Для нативных подписок Experimental 0.8.8 — отдельный `config/split_experimental.json` в закрытом проекте; для цепочки DNS Experimental 0.8.9+ — `config/split_experimental_0.8.9_over.json`. Применение на роутере — отдельная операция загрузчика.

## Источники и порядок работы

1. Прочитайте задачу и текущий целевой файл или пару файлов. Уточняйте только недостающие данные, необходимые для изменения.
2. Полностью прочитайте [справочник формата](config-format.ru.md). Имена UCI сверяйте с установленной версией Podkop.
3. Сохраняйте посторонние записи. Для схем 1–3 из подписки извлекайте отдельные поддерживаемые proxy URI: URL подписки не является элементом `urltest_proxy_links`. В схеме 4 передавайте сам HTTPS-адрес отдельным источником `sources`.
4. В закрытом проекте прочитайте правила отбора стран и серверов для `notUnderSanctions`. По принятому правилу доверяйте явно указанной провайдером стране, неизвестную страну в этот пул не добавляйте. Сверяйте поддержку региона сервисами, но не называйте отбор по стране проверкой доступности каждого узла.
5. Подготовьте добавления, явные удаления и заголовки групп. Не придумывайте реальные реквизиты, DNS или результаты сетевых проверок.
6. Обновите `revision`, проверьте структуру, равенство данных имеющейся пары JSON/JSONC и diff без вывода секретов. Для обоих файлов `split_experimental*.json` отдельные JSONC-копии не создаются.

## Итоговый файл и совместимость

Формат 3 имеет пять обязательных ключей:

- `schema_version`: число `3`;
- `revision`: понятная метка изменения, например `2026-10-25-split-01`;
- `main`: объект параметров основной секции;
- `notUnderSanctions`: объект параметров секции с отдельно отобранными выходными серверами;
- `settings`: объект разрешённых общих параметров либо `{}`.

Он требует программы 0.2.0+. Старые `config/main.json` и `config/main.jsonc` остаются в формате 2 для работающих загрузчиков 0.1.x. Не заменяйте файл по старому URL схемой 3: сначала обновляют программу на роутере, затем меняют ссылку на `config/split.json` или `config/split.jsonc`, проверяют источник и применяют. Возврат старой ссылки не удаляет созданную вторую секцию.

[Полный искусственный пример](../examples/main.json) показывает обе секции, URLTest, заголовки групп, парные операции переноса и шесть общих настроек. Все proxy URI, идентификаторы и адреса вымышлены: используются `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `example.com` и `example.net`. Пример не предоставляет работающий VPN, DNS или адрес проверки.

## Нативные подписки Experimental 0.8.8

Для этого варианта используйте **схему 4**, программу **0.3.0 или новее** и [искусственный пример](../examples/experimental.json). Файл рассчитан на уже установленный Podkop Experimental 0.8.8 с `settings.config_version: "2"`. Загрузчик проверяет этот формат перед применением и не переводит стабильный Podkop на Experimental. Прежние файлы схем 2/3 сохраняются по своим URL для стабильного и прежнего Experimental; на нативном UCI-формате применение схем 1–3 отклоняется с `experimental_config_required`, чтобы устаревшие поля не дали ложный успех.

Сохраните маршрутизацию в `main` и `notUnderSanctions`, заменив описание отдельных прокси на:

- `sources`: именованные источники с `type: "subscription"`, HTTPS-полем `url`, необязательными `label` и `update_interval` (`auto` либо положительная длительность `m`, `h`, `d`);
- `members`: именованные строки правил с `section`, `source`, `role`, фильтрами `include` / `exclude` и необязательным `via`;
- `replace_members`: явный список правил, прежний состав строк которых нужно заменить, например `["main", "notUnderSanctions"]`.

У источника и строки должны быть стабильные уникальные ID; один источник можно использовать в обеих секциях с разными фильтрами. `replace_members` убирает только старые строки названных правил, отсутствующие в новом `members`; остальные источники и правила сохраняются. Если для этого нужны удаления, разрешите их и применение всех участвующих параметров. Нельзя обходить выключенные галочки пользователя. Фильтры — точные списки: переданный `[]` очищает фильтр, а отсутствие ключа сохраняет прежнее значение.

Podkop сам скачивает подписки и обновляет состав серверов по `sources.<id>.update_interval`. Перед включением источника отдельно проверьте ответ с заголовками клиента Podkop: версия 0.8.8 принимает только URI построчно или их Base64-представление, а Xray/sing-box JSON и Clash YAML отклоняет. Не угадывайте параметры URL, которые якобы меняют формат. «Тест соединения» нашей программы проверяет только файл настроек, подписки и VPN-соединения он не проверяет.

Фильтры 0.8.8 не являются регулярными выражениями: `exclude` проверяется первым, `include` означает «хотя бы одно совпадение», пустой `include` принимает все имена. Обычное слово сравнивается с началом слов названия без учёта регистра; флаг, пробел или пунктуация в фильтре означают поиск буквальной подстроки. Регистр дублировать не нужно, а кириллица и латиница — разные слова. Используйте флаги и полные русские/английские названия стран, избегая неоднозначных коротких кодов `US` / `DE`. Для `main` исключайте «Обход». Для `notUnderSanctions` сохраняйте явный список разрешённых стран и исключения запрещённых/неопределённых и тестовых (`test`, `тест`) выходов. Новая неизвестная страна или новое неподтверждённое название не должны пройти в этот пул до проверки. Нефильтрованный fallback в `notUnderSanctions` не добавляйте.

Параметры URLTest в нативном формате находятся в `settings.urltest_*`; поля `connection_type`, `proxy_config_type` и `urltest_proxy_links` в секциях для этого файла не нужны. Заголовки `comment`, правила маршрутизации и ограничение пользовательских подсетей только IPv4 сохраняются. Нативный Podkop хранит последние списки подписок на flash для запуска без сети; хранение временных данных нашей программы в RAM этого не меняет.

## Цепочка DNS Experimental 0.8.9+

Для новых DNS-настроек нужны **программа 0.3.1+** и реально установленный **пакет `podkop-exp` версии 0.8.9+** с нативным UCI-форматом 2. Сохраняйте прежний `config/split_experimental.json` для 0.8.8 без изменений; новый вариант записывайте в **`config/split_experimental_0.8.9_over.json`**. Суффикс `_over` обозначает вариант для версии 0.8.9 и новее. [Отдельный искусственный пример](../examples/experimental-dns.json) содержит неработающие демонстрационные адреса, а не рекомендованные DNS-серверы.

Добавляйте на верхнем уровне `dns_servers` — непустой упорядоченный массив от 1 до 32 строк с уникальными UCI-именами `name`. Типы: `doh`, `dot`, `udp`, `provider`. Для первых трёх нужен `server` без схемы `https://`; путь допустим только у DoH. У `provider` ключ `server` запрещён: Podkop получает актуальные DNS от WAN, поэтому адрес из интерфейса конкретного роутера в файл не копируют.

Это полный список DNS, а не добавления: отсутствующий `dns_servers` сохраняет текущую цепочку, переданный массив задаёт весь состав и порядок. Прежние DNS-строки, которых в нём нет, удаляются только с разрешёнными автоматическими удалениями; иначе всё применение отклоняется с `dns_delete_disabled`. Один локальный флажок `settings.dns_servers` защищает весь список. Отдельный флажок `settings.dns_mode` защищает строку `settings.dns_mode`: `order` опрашивает по порядку, `fastest` предпочитает ранее самый быстрый ответ. Для резервов в конце списка нужен `order`; в `fastest` расположение не задаёт приоритет. Не добавляйте `delete` или `comment` внутрь `dns_servers`.

`config_version: "2"` есть и у 0.8.8, поэтому не доказывает поддержку цепочки DNS. Если новые DNS-поля разрешены локальными галочками, загрузчик перед записью проверяет установленный пакет и при неподходящей или неопределённой версии отклоняет весь конфиг с `experimental_dns_version_required`. При выключенных обоих новых DNS-полях они не применяются; остальные разрешённые параметры могут обновляться по обычным правилам схемы 4. Сама 0.8.8 игнорирует новые UCI DNS-строки и продолжает использовать прежний DNS, но выдавать это за успешное применение цепочки нельзя.

«Тест соединения» проверяет только скачивание и формат JSON и может пройти даже на 0.8.8; проверка установленной версии относится к применению. Тест не отправляет DNS-запросы, не проверяет доступность резолверов и не меняет роутер. Правила маршрутизации, источники и глобальные параметры URLTest берите из прежнего файла без посторонних изменений.

## Распределение между секциями

`main` содержит основной пул и сервисы без выбранного требования к региону выхода. `notUnderSanctions` предназначена для сервисов, которым нужен подходящий регион, и необходимых им общих зависимостей. Само название секции не проверяет санкции и не гарантирует доступность.

Загрузчик ставит `notUnderSanctions` перед `main`, сохраняя взаимный порядок остальных секций. Проверяйте доменные суффиксы, community lists и общие IPv4/CDN: сеть первой секции может перехватить домен второй. Не называйте общие сети исключительной собственностью одного сервиса. Группируйте связанные зависимости последовательно и документируйте известные пересечения и дату DNS-снимков.

URLTest выбирает среди серверов по соединению и задержке. HTTP 403 от AI-сервиса может не считаться ошибкой URLTest. Успешная проверка Google и разрешённая страна в URI не доказывают доступ к OpenAI, Claude или Gemini.

В программе 0.2.0 отдельный локальный контроллер OpenAI управляет внешним выбором только `notUnderSanctions`, сохраняя тип и пул URLTest в конфиге. Он проверяет фиксированный запрос без ключа и переключает узлы при подтверждённом региональном отказе или повторяющихся сетевых ошибках. Результат принимается только при подтверждённом маршруте этого запроса через нужную группу и узел. Контроллер не определяет географию IP и не проверяет остальные сервисы. Его флаг не включают в файл; [алгоритм и ограничения](https://github.com/hayOfLife/podkop-config-auto-updater/blob/main/docs/openai-check.ru.md) описаны в документации программы.

Поле **«URLTest ссылка для проверки»** — `<секция>.urltest_testing_url` для схем 1–3 или `settings.urltest_testing_url` для схемы 4, строка полного HTTP/HTTPS-адреса. Сохраняйте текущую ссылку, если пользователь не просил её заменить. Искусственный адрес из примера в рабочий конфиг не переносите.

## Добавление, удаление и перенос

Строка массива добавляет запись без нового дубля. `{"value": "точное значение", "delete": true}` удаляет её; отсутствие записи в файле ничего не удаляет на роутере. Одиночная строка заменяет параметр, а одиночное удаление требует точного совпадения текущего значения. Флаги UCI — строки `"0"` / `"1"`.

При переносе добавьте запись в целевую секцию и оставьте её `delete` в исходной. Если запись ещё есть в источнике, а удаление или применение участвующего поля выключено, загрузчик отклонит всё применение с `section_move_blocked`. На чистом роутере, где удалять нечего, добавление может выполняться без разрешения удалений. Обычные несвязанные удаления при выключенной галочке пропускаются.

Сохраняйте операции удаления до перехода всех роутеров. Удаление самой операции из файла не возвращает адрес, но вручную восстановленная запись перестанет удаляться. Чтобы вернуть адрес через конфиг, замените удаление строкой добавления. Внутри одного списка добавление и удаление одного нормализованного значения запрещены. Пустой массив не очищает список.

## Подписи групп в файле и Podkop

Для отображения заголовка в текстовом поле Podkop добавляйте `{"comment": "Название сервиса"}` над группой внутри `user_domains` или `user_subnets`. Это отдельный элемент схем 3/4; при наличии пары JSON/JSONC он одинаковый в обеих копиях. Подпись у каждой строки не нужна. Подробные ограничения находятся в [справочнике](config-format.ru.md#заголовки-групп-в-полях-podkop).

```json
"user_domains": [
  {"comment": "Демонстрационный сервис"},
  "example.com",
  "api.example.net"
]
```

В Podkop появится строка `// Демонстрационный сервис`. Для динамического списка одновременно укажите `user_domain_list_type: "text"` или `user_subnet_list_type: "text"`; без явного перехода заголовки отклоняются. Ручные записи сохраняются при объединении. Заголовки не допускаются в прокси или community lists.

Комментарии JSONC `//` и `/* */` вне строк можно дополнительно использовать для пояснения самого файла. Они автоматически не переносятся в Podkop. Заголовки для интерфейса передаются только через элементы `comment`. Данные подписанной и строгой копий должны совпадать полностью.

## Общие настройки

В схемах 1–3 блок `settings` допускает только:

| Настройка | Ключ |
| --- | --- |
| Тип протокола DNS | `dns_type` |
| DNS-сервер | `dns_server` |
| Bootstrap DNS-сервер | `bootstrap_dns_server` |
| Скачивать списки через Proxy/VPN | `download_lists_via_proxy` |
| Частота обновления списков | `update_interval` |
| Скачивать списки через выбранную секцию | `download_lists_via_proxy_section` |

Значения описаны в [справочнике](config-format.ru.md#dns-и-загрузка-списков). Частота списков Podkop не задаёт время получения JSON нашей программой. Токен, расписание 03:00–03:30, галочки отключения IPv6 и контроля OpenAI относятся к локальным настройкам; в файл их не включайте.

В схеме 4 дополнительно разрешены `config_version: "2"`, `dns_mode` для Experimental 0.8.9+ и пять глобальных параметров `urltest_check_interval`, `urltest_tolerance`, `urltest_testing_url`, `urltest_download_check`, `urltest_download_url`. Обязательная проверка уже установленного нативного формата действует и без `config_version` в скачанном файле.

## Проверка перед сохранением

- Проверьте JSON и схему, имена/типы полей, размер и количество элементов. Проверка синтаксиса не проверяет серверы.
- Сравните итоговые операции с задачей: нет потерь адресов при разделении, конфликтов внутри списков и случайных добавлений/удалений.
- В пользовательских подсетях рабочего файла оставляйте только IPv4; IPv6 не добавляйте.
- Учтите сравнение доменов без регистра, канонические подсети и буквальное сравнение proxy URI.
- Проверьте, что каждый управляемый URLTest после применения не остаётся пустым и для резервирования имеет несколько подходящих серверов. Если узлы не проверены, так и напишите.
- Для DNS-варианта проверьте полный состав и порядок `dns_servers`, уникальность имён, отсутствие `server` у `provider`, режим `dns_mode` и требования программы 0.3.1 / Podkop Experimental 0.8.9+. Отдельный тест JSON не подтверждает совместимость установленной версии или ответы DNS.
- Для схемы 4 проверьте ссылки `members` на `sources`, непустой состав каждого заменяемого правила и точные списки фильтров. Наличие источников в JSON не доказывает, что подписки скачались и дали подходящие серверы.
- Проверьте возможность переноса при локальных запретах, порядок секций и идемпотентность повторного применения.
- Убедитесь, что секция скачивания списков существует и является Proxy/VPN. Если состояние роутера неизвестно, не объявляйте проверку живого состояния выполненной.
- Сверьте равенство имеющихся пар JSON/JSONC и одинаковых общих документов и примеров в публичном и приватном проектах. Оба варианта `split_experimental*.json` хранятся без дублирующего JSONC.
- Не публикуйте рабочие proxy URI в открытом проекте, примерах или отчётах. Токен GitHub не входит даже в закрытый JSON.

В отчёте укажите файлы, revision, состав секций и границы проверки. Не утверждайте, что настройки применены на роутере, регион принят сервисом или резервирование работает, если проверены только файлы и тестовые фикстуры.
