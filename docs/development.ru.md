# Разработка и границы проверки

## Архитектура

Один пакет `luci-app-podkop-config-auto-updater` устанавливает страницу LuCI, собственный UCI-конфиг, службу procd и загрузчик на ucode. Это использует штатные компоненты OpenWrt и не требует Python на роутере. Данные владельца находятся в отдельном закрытом репозитории и не включаются в пакет или артефакты сборки.

`core.uc` проверяет формат и объединяет записи. `source.uc` преобразует поддерживаемую ссылку GitHub в Contents API. `worker.uc` выполняет загрузку и расписание. `transaction.uc` записывает копию UCI в отдельном каталоге, сохраняет резервную копию, повторно проверяет исходный файл и атомарно заменяет его. Shell-обёртка удерживает `flock` до окончания операции. Права rpcd разрешают только собственный UCI и две фиксированные команды — чтение статуса и обновление.

Загрузка ограничена HTTPS, 60 секундами и 1 МиБ. Перенаправления не выполняются. Токен передаётся curl через приватный временный файл заголовков, а не через аргумент процесса. Текст конфигурации и ошибки curl не выводятся в статус или журнал.

## Совместимость и ограничения

Целевые версии — OpenWrt 24.10 и 25.12 с современным LuCI, ucode и Podkop с полями `urltest_proxy_links`, `user_domains_text`, `user_subnets_text`. Сборка использует официальный SDK 24.10.7 / 25.12.5 и создаёт настоящие IPK / APK; скрипты не зависят от архитектуры процессора.

Изменения в LuCI должны быть сохранены до обновления. Проверяются стандартные каталоги отложенных UCI-изменений и актуальное содержимое файла перед заменой. Это защищает обычный сценарий ручного редактирования, но не является общей транзакционной блокировкой всех сторонних писателей UCI: не запускайте другие автоматические загрузчики одновременно.

Успешный exit code команды перезапуска не доказывает работоспособность всех серверов или конечную готовность Sing-box. Версия ещё не проверена установкой на живом роутере. Нет цифровой подписи JSON, anti-rollback по revision, авторизации личного HTTP-сервера или автоматической выдачи токена GitHub. Доверие определяется HTTPS, правами репозитория и доступом администратора к роутеру.

## Проверки и сборка

Рабочий каталог — корень репозитория. Для проверок JavaScript/JSON нужен Node.js:

```sh
node scripts/checkSource.mjs
git diff --check
```

Ожидается код `0`. Эти проверки не меняют рабочие настройки и не подтверждают выполнение на OpenWrt.

Для тестов ucode нужен Linux, `/bin/sh`, Git, CMake, C-компилятор, заголовки json-c/OpenSSL и доступ к GitHub:

```sh
sh scripts/testNative.sh
```

Скрипт собирает закреплённые версии ucode/UCI/libubox в `${RUNNER_TEMP:-/tmp}/podkop-config-auto-updater-tools`, затем запускает тесты объединения, расписания, записи настоящим UCI, отказа при параллельной правке и отката. Ожидается код `0` и строки `checks passed`. Повторный запуск требует нового временного каталога; существующие инструменты скрипт не удаляет. Для очистки удалите только созданный им каталог после проверки пути. Тесты используют временные фикстуры и не обращаются к вашему роутеру или VPN.

Workflow `Verify and build` выполняет тесты и две SDK-сборки. Успех проверки синтаксиса, fixture-тестов и упаковки оценивается отдельно от установки и работы на живом роутере. Для изменения интерфейса дополнительно проверьте страницу в LuCI: сохранение флажков, ссылку под токеном, ручное обновление и отображение ошибки без секретов.

## Обновление документации

Подход принят из документации Sheepfold: один документ отвечает за одну задачу, команды содержат условия запуска и ожидаемый результат, реализованные функции отделены от непроверенных на устройстве. При изменении схемы, значения по умолчанию или ошибки обновляйте соответствующий справочник вместе с кодом. Проверяйте локальные ссылки и не помещайте реальные серверы, токены или резервные копии в публичные примеры.
