# Разработка и границы проверки

## Архитектура

Один пакет `luci-app-podkop-config-auto-updater` устанавливает страницу LuCI, собственный UCI-конфиг, службу procd и загрузчик на ucode. Это использует штатные компоненты OpenWrt и не требует Python на роутере. Данные владельца находятся в отдельном закрытом репозитории и не включаются в пакет или артефакты сборки.

`core.uc` объединяет три основных списка и рассчитывает расписание. `config.uc` поддерживает форматы 1/2/3/4, параметры `main` и `notUnderSanctions`, заголовки групп в текстовых списках и разрешённые общие настройки. `experimental.uc` проверяет и объединяет нативные источники подписок и строки правил схемы 4. `source.uc` преобразует поддерживаемую ссылку GitHub в Contents API. `worker.uc` выполняет загрузку и расписание; режим `test` возвращает результат скачивания и проверки без вызова транзакции или записи статуса применения. `transaction.uc` записывает копию UCI в отдельном каталоге, сохраняет резервную копию, повторно проверяет исходный файл и атомарно заменяет его. Shell-обёртка удерживает `flock` до окончания операции. Права rpcd разрешают только собственный UCI и фиксированные команды статуса, тестирования, применения конфига и обновления двух программ. Отдельный скрипт `ipv6` управляет собственным sysctl-файлом и восстанавливает сохранённые флаги интерфейсов.

Схема 3 применяет обе секции, общие параметры и порядок одной транзакцией и одним перезапуском Podkop. `notUnderSanctions` переносится перед `main` штатным `uci.cursor.reorder()`; взаимный порядок остальных секций сохраняется. Старые схемы не меняют вторую секцию и порядок. Перенос элемента между секциями требует парных удаления/добавления и проверяется до фильтрации локально запрещённых параметров: частичное применение отклоняется, если исходная запись ещё присутствует. Метаданные `comment` допускаются только в массивах доменов и подсетей схем 3/4; они превращаются в `//` в текстовом UCI-поле, а не в адреса правила. Повторное применение не размножает заголовки. Контракт и миграция описаны в [справочнике](config-format.ru.md).

Схема 4 версии 0.3.0 сохраняет эту транзакцию и заголовки, добавляя именованные UCI-секции `source` / `member`. Применение требует уже установленного `settings.config_version: "2"` и не запускает миграцию Podkop. Все ссылки на источники проверяются по итоговому UCI до записи. `include` / `exclude` заменяются точными списками; `replace_members` явно удаляет прежние строки только названных правил. Защита `sources.<id>.<поле>`, `members.<id>.<поле>` и `membership.<правило>` вместе с разрешением удалений исключает частичную смену состава. Неназванные источники и правила сохраняются. Форматы 1–3 и их файлы не переводятся на эту схему автоматически; на уже нативном UCI они отклоняются с `experimental_config_required`, чтобы не записывать устаревшие поля с ложным результатом применения.

Сами подписки наша программа не получает и не конвертирует: это делает Podkop Experimental 0.8.8 со своими заголовками клиента, парсером URI/Base64, обновлением и кэшем `/usr/share/podkop/subscriptions` на flash. Поддержка схемы 4 не означает поддержку произвольного Xray JSON в ответе подписки. Режим `test` ограничен JSON загрузчика; сетевые проверки источников и конечная готовность нативных серверов проверяются отдельно.

`health.uc` классифицирует ограниченный ответ OpenAI и рассчитывает повторные проверки; `health-worker.uc` управляет состоянием и только внешним selector `notUnderSanctions-out`; `health-io` выполняет фиксированные операции curl и Clash API. Локальная настройка `openai_check_enabled` по умолчанию включена, но автоматические проверки требуют также `enabled`. Флаг отсутствует в удалённом JSON. Проверка выполняет IPv4 GET без API-ключа обычным маршрутом Podkop; `/connections` должен подтвердить точный исходящий порт, хост, группу и конечный узел. Без такого подтверждения запрещены успешный статус, исключение узла и переключение. Новые порты, mixed inbound и правила firewall не создаются. [Полный контракт контроля](openai-check.ru.md).

Контроллер сохраняет предыдущий выбор и своё владение группой только в RAM. При выключении он возвращает предыдущий вариант лишь при совпадении текущего выбора со своим и наличии предыдущего в группе. Чужое изменение прерывает текущий проход; недоступный API оставляет возврат для повторной попытки. При `route_unconfirmed` временный выбор освобождается с теми же ограничениями, без выбора другого узла по ответу запроса. Не удаляйте `cache.db`: Podkop может штатно сохранять туда выбор API независимо от RAM-состояния дополнения. Команда выбора не повторяется при каждом успешном запросе. Все временные тела ответов и секрет локального Clash API остаются в приватных временных файлах, публичный статус содержит только разрешённые поля и коды ошибок.

Остановка освобождает группу в `service_stopped` после daemon; `health-release` ждёт общий lock до 180 секунд и при ошибке возвращает ненулевой код. Исключение — подтверждённая командой `software status` активная установка самого дополнения (`running/self/installing`): возврат пропускается, RAM-состояние принимает новая служба. [Условия и ограничения остановки](openai-check.ru.md#ручной-выбор-и-выключение).

Обновление программ реализовано в `software.uc`, обёртке `software` и адаптере `software-io`. Фоновый процесс наследует блокировки, а команды пакетного менеджера закрывают эти дескрипторы, чтобы перезапущенные службы не удерживали их. Исполняемые файлы копируются во временный каталог перед запуском и переживают самообновление. При обновлении IPK процедура удаления не восстанавливает IPv6; APK выполняет эту процедуру только при удалении. Релизы и пакеты ограничены фиксированными репозиториями, имена и SHA-256 проверяются до установки. Переустановка той же версии и понижение основного пакета не выполняются.

Загрузка ограничена HTTPS, 60 секундами и 1 МиБ. Перенаправления не выполняются. Токен передаётся curl через приватный временный файл заголовков, а не через аргумент процесса. Текст конфигурации и ошибки curl не выводятся в статус или журнал.

Начиная с 0.2.2 программа запускает ручное применение из LuCI через `run update-start`: фоновый процесс наследует общий lock и отдельный `update.lock`, а интерфейс читает этап и результат по `operation`. Команда `run update` остаётся синхронной. `io` закрывает оба дескриптора перед загрузкой или перезапуском, чтобы дочерние службы не удерживали блокировки после завершения worker. Статус `running` без занятого `update.lock` превращается при чтении в `update_interrupted`. Промежуточные этапы пишутся в RAM без вывода в stdout синхронной команды; успешный результат публикуется после завершения транзакции и команды перезапуска.

В 0.3.0 сброс настроек запускается отдельным `reset-start` после предупреждения LuCI. Он использует общую блокировку, проверку отложенных UCI-изменений, фоновый статус и временную копию прежнего файла в RAM. Штатный UCI загружается как данные из официального тега точной установленной версии `podkop` / `podkop-exp`, а не из последней ветки и не из неподтверждённого `/rom`. Отказ загрузки или проверки происходит до остановки службы и замены `/etc/config/podkop`. После проверки Podkop останавливается, штатный файл записывается и служба остаётся остановленной: исходный конфиг не содержит готового подключения. При ошибке записи после остановки программа пытается восстановить прежние файл и состояние службы. Настройки дополнения сохраняются, поэтому его расписание может затем повторно применить JSON и запустить Podkop обычным путём. Сброс не удаляет пакеты и не исполняет скачанные скрипты. [Область сброса и предупреждение](operations.ru.md#сброс-настроек-podkop-к-стандартным).

## Совместимость и ограничения

Целевые версии — OpenWrt 24.10 и 25.12 с современным LuCI и ucode. Схемы 1–3 рассчитаны на Podkop с полями `urltest_proxy_links`, `user_domains_text`, `user_subnets_text`; схема 4 — на нативный формат Podkop Experimental 0.8.8 с `source`, `member` и `settings.config_version: "2"`. Сборка использует официальный SDK 24.10.7 / 25.12.5 и создаёт настоящие IPK / APK; скрипты не зависят от архитектуры процессора.

Поддержка `//` в текстовых полях и порядка секций сверена по исходникам Podkop 0.7.24 и Experimental 0.8.1. Это проверка формата и построения правил, а не подтверждение работы на конкретном роутере. В 0.2.0 кнопка обновления поддерживала только стабильный Podkop; в 0.2.1 добавлено обновление установленного `podkop-exp` из последнего релиза `podkop-net/podkop-experimental`. Установленный `podkop` продолжает обновляться из `itdoginfo/podkop`. Смена ветки, удаление конфликтующего пакета и первая установка Podkop этой кнопкой не выполняются.

Действие RPC остаётся `podkop`; определённая ветка передаётся в статусе как `variant: stable` либо `variant: experimental`. Для Experimental архитектура берётся из `DISTRIB_ARCH` в `/etc/openwrt_release`, а в имени IPK/APK `_` заменяется на `-`. Выбираются backend `podkop-exp`, интерфейс `luci-app-podkop-exp` и уже установленный русский перевод; SHA-256 каждого файла проверяется по `digest` GitHub API. Конфликт двух установленных пакетов, отсутствие обоих, неизвестная архитектура или отсутствие подходящего файла останавливают обновление. Сравнение версий штатным пакетным менеджером допускает установку только более новой версии основного пакета; одинаковая версия и понижение пропускаются. Реальная установка нового пути Experimental пока не проверена.

Перевод Experimental имеет собственную версию сборки: при обновлении ядра его берут из того же релиза с проверкой SHA-256 без сравнения с номером ядра; после установки строго сверяют версии core/UI, а для перевода — наличие корректной версии.

URLTest не является проверкой поддерживаемого региона: в ядре Experimental 0.8.1 HEAD-тест не проверяет HTTP-статус. Отдельный контроллер OpenAI проверяет только достижение обычной авторизации фиксированного endpoint и может временно исключать узлы. Он не проверяет географию IP, аккаунт или остальные AI-сервисы. Нужен живой Clash API: для Experimental сведения берутся через локальный Unix API работающего процесса, для стабильного Podkop — из его конфигурации с последующей проверкой API. Если маршрут запроса не подтверждается, результат остаётся `route_unconfirmed`. Название `notUnderSanctions` обозначает назначение заранее отобранного пула. Общие IP/CDN могут пересекаться между сервисами; приоритет секций не создаёт отдельного преимущества доменов над подсетями.

Изменения в LuCI должны быть сохранены до обновления. Проверяются стандартные каталоги отложенных UCI-изменений и актуальное содержимое файла перед заменой. Это защищает обычный сценарий ручного редактирования, но не является общей транзакционной блокировкой всех сторонних писателей UCI: не запускайте другие автоматические загрузчики одновременно.

Успешный exit code команды перезапуска не доказывает работоспособность всех серверов или конечную готовность Sing-box. Версия ещё не проверена установкой на живом роутере. Нет цифровой подписи JSON, anti-rollback по revision, авторизации личного HTTP-сервера или автоматической выдачи токена GitHub. Доверие определяется HTTPS, правами репозитория и доступом администратора к роутеру.

## Проверки и сборка

Рабочий каталог — корень репозитория. Для проверок JavaScript/JSON нужен Node.js:

```sh
node scripts/checkSource.mjs
node tests/actionsUiTest.mjs
git diff --check
```

Ожидается код `0`. Эти проверки не меняют рабочие настройки и не подтверждают выполнение на OpenWrt.

Для тестов ucode нужен Linux, `/bin/sh`, Git, CMake, C-компилятор, заголовки json-c/OpenSSL и доступ к GitHub. Проверки команд дополнительно используют Python 3, `sudo`, `chroot`, `ldd` и стандартные утилиты Linux:

```sh
sh scripts/testNative.sh 24.10
sh scripts/testNative.sh 25.12
```

Скрипт собирает закреплённые версии ucode/UCI/libubox в `${RUNNER_TEMP:-/tmp}/podkop-config-auto-updater-tools-<series>`, затем запускает тесты объединения, расписания, записи настоящим UCI, отказа при параллельной правке и отката. `tests/routerActionsTest.py` выполняет настоящие команды в отдельном chroot с подставными загрузчиком и пакетными менеджерами: проверяет отсутствие изменений при тесте, SHA-256 до установки, оба формата пакетов, замену собственного кода, ошибки и отсутствие понижения. Созданный chroot удаляется после прогона; реальные пакеты и настройки машины не меняются. Ожидается код `0` и строки `checks passed` / `scenarios passed`. Повторный запуск требует нового временного каталога; существующие инструменты скрипт не удаляет. Для очистки удалите только созданный им каталог после проверки пути. Тесты используют временные фикстуры и не обращаются к вашему роутеру или VPN.

Workflow `Verify and build` выполняет тесты и две SDK-сборки. `python3 tests/ipv6Test.py` проверяет отключение и восстановление IPv6 только в подставном дереве `/proc` временного каталога. Успех проверки синтаксиса, fixture-тестов и упаковки оценивается отдельно от установки и работы на живом роутере. Для изменения интерфейса дополнительно проверьте страницу в LuCI: сохранение флажков, ссылку под токеном, ручное обновление и отображение ошибки без секретов.

## Формат контрольных сумм релиза

Файл `SHA256SUMS` публикуйте в UTF-8 без BOM, с переносами строк LF и завершающим LF. Каждая строка содержит SHA-256, два пробела и точное имя артефакта; для каждого пакета должна быть ровно одна строка. CRLF недопустим: символ CR остаётся в имени файла при сравнении в установщике и приводит к ошибке «В релизе нет единственной контрольной суммы пакета».

При генерации через Python на Windows явно задавайте `newline="\n"` при открытии текстового файла либо записывайте готовые UTF-8-байты через `write_bytes()`. Перед публикацией проверьте отсутствие BOM и CR, совпадение сумм с артефактами и выбор ровно одной строки для каждого имени пакета. После загрузки повторно скачайте опубликованный файл и сверьте его байты с проверенной локальной копией.

23 октября 2026 года в релизе 0.1.3 исправлены переносы строк `SHA256SUMS` с CRLF на LF. Пакеты и их контрольные суммы не менялись; ошибка останавливала установщик до вызова пакетного менеджера.

## Обновление документации

Один документ отвечает за одну задачу, команды содержат условия запуска и ожидаемый результат, реализованные функции отделены от непроверенных на устройстве. При изменении схемы, значения по умолчанию или ошибки обновляйте соответствующий справочник вместе с кодом. Проверяйте локальные ссылки и не помещайте реальные серверы, токены или резервные копии в публичные примеры.

Матрица проверок использует ucode из OpenWrt 24.10.7 (3f64c8089bf3ea4847c96b91df09fbfcaec19e1d) и 25.12.5 (85922056ef7abeace3cca3ab28bc1ac2d88e31b1). Объявления export function завершаются точкой с запятой, обязательной в этих версиях компилятора. Проверки на более новом ucode не заменяют эту матрицу.

Для схемы 3 проверяйте также обе секции с настоящим UCI, изменение только порядка, независимые локальные запреты, атомарный отказ переноса, сохранение ручных записей и заголовков, переход dynamic → text, отсутствие повторных изменений и обратную совместимость схем 1/2. Общие `AGENTS.md`, справочник, инструкцию автору и искусственный пример синхронизируйте побайтово с закрытым репозиторием. Новый формат публикуется по отдельному URL `config/split.json` / `split.jsonc`, чтобы старые загрузчики продолжали получать схему 2.

Для схемы 4 проверяйте отказ на старом UCI-формате без записи, создание типов `source` / `member`, коллизии имён, ссылки на итоговые источники, точную замену и очистку фильтров, защищённые поля, запрет необходимых удалений, явный `replace_members`, сохранение посторонних правил и повторное применение без изменений. Искусственный `examples/experimental.json` должен проходить валидацию и побайтово совпадать в обоих репозиториях. Рабочий `config/split_experimental.json` хранится одним файлом в закрытом проекте; секретные URL не должны попасть в публичные фикстуры или отчёт. Проверки с подставными источниками не доказывают получение реальных подписок и работу VPN на роутере.

Для сброса проверяйте обязательное подтверждение интерфейса, отсутствие изменений до успешной загрузки и проверки штатного файла, выбор тега установленной версии, отказ при отложенных UCI-изменениях и занятой блокировке, замену всех настроек Podkop, конечное остановленное состояние, сохранение настроек дополнения и восстановление при ошибке записи. Используйте подставные файлы, загрузчик и службу; реальный сброс рабочего роутера не является частью этих проверок.

Для контроля OpenAI отдельно проверяйте строгий JSON отсутствующей авторизации, региональный код, три сетевые ошибки, паузы 429/5xx, отсутствие переключения при неподтверждённом маршруте, совпадение порта/хоста/цепочки, ограничение двух проверок за проход, сохранение ручного выбора и условное восстановление при выключении. Проверяйте, что `test` и `status` не запускают сетевые проверки, а `main` и firewall не меняются. Тесты классификации находятся в `tests/healthTest.uc`; проверки runtime и UI должны использовать подставной API и фикстуры, без реального роутера или VPN. В [CI версии 0.2.0](https://github.com/hayOfLife/podkop-config-auto-updater/actions/runs/40196543589) прошли обе матрицы OpenWrt, включая 44 проверки классификации и 34 сценария контроллера; собраны IPK и APK. Проверка на реальном роутере остаётся отдельным этапом.

Регрессия дробного `sleep` воспроизводится в `routerHealthTest.py`: внешняя команда принимает только целые секунды, а контроллер использует паузу ucode в миллисекундах. Сценарии `routerActionsTest.py` задерживают перезапуск до сигнала из теста и проверяют фоновый запуск, `busy`, конечный результат, ошибку отката и прерванную операцию. UI-тесты проверяют отсутствие преждевременного успеха и продолжение опроса после потери связи. В [CI версии 0.2.2](https://github.com/hayOfLife/podkop-config-auto-updater/actions/runs/40300801224) обе матрицы OpenWrt прошли: 94 сценария команд, 34 сценария контроля OpenAI, 72 проверки LuCI и остальные проверки workflow. Установка этой версии на реальный роутер пока не выполнена.
