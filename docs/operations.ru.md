# Установка и обслуживание

Инструкция для администратора OpenWrt. Команды выполняются в SSH роутера от `root`, оболочка `/bin/sh`, рабочий каталог `/tmp`. Перед установкой сохраните резервную копию через LuCI. Нужны установленный Podkop, точные часы, HTTPS-доступ к источнику и свободное место для зависимостей.

## Установка и обновление

Рекомендуемый путь — установочный скрипт. В SSH роутера, от `root`, из `/tmp` выполните:

```sh
uclient-fetch -O /tmp/podkop-config-auto-updater-install.sh https://raw.githubusercontent.com/hayOfLife/podkop-config-auto-updater/main/install.sh && sh /tmp/podkop-config-auto-updater-install.sh
```

Скрипт поддерживает только стабильные ветки 24.10 и 25.12, требует уже установленный Podkop, `jsonfilter`, `sha256sum` и HTTPS-загрузчик. Он получает последний опубликованный релиз, выбирает подходящий IPK/APK, сверяет SHA-256, обновляет индекс пакетов и устанавливает только приложение с его зависимостями. Он не прошивает роутер и не выполняет массовое обновление пакетов. Если в релизе нет нужного файла или сумма не совпадает, установка не начинается.

Ожидается код `0` и сообщение «Готово». Повторный запуск обновляет программу, сохраняя её настройки; копия существующего конфига загрузчика сохраняется в `/tmp/podkop-config-auto-updater/before-install-config`. Если опубликованного релиза пока нет, скрипт сообщит об ошибке получения релиза. Удаление и восстановление описаны в соответствующих разделах этой инструкции.

Для ручной установки используйте следующий путь.

Скачайте пакет из [последнего релиза](https://github.com/hayOfLife/podkop-config-auto-updater/releases/latest) и загрузите его на роутер в `/tmp`. Используйте IPK только на OpenWrt 24.10, APK только на 25.12. Имена файлов ниже постоянны для соответствующих веток OpenWrt.

Для OpenWrt 24.10:

```sh
opkg update
opkg install /tmp/luci-app-podkop-config-auto-updater-openwrt-24.10.ipk
```

Для OpenWrt 25.12:

```sh
apk update
apk add --allow-untrusted /tmp/luci-app-podkop-config-auto-updater-openwrt-25.12.apk
```

Ожидается код `0` и установленный `luci-app-podkop-config-auto-updater`. `--allow-untrusted` требуется для локального пакета без доверенного ключа подписи; не отключайте проверку TLS. Зависимости устанавливаются из настроенных репозиториев OpenWrt. Эти команды меняют состав пакетов, но не обновляют всё окружение. Для обновления повторите установку с новым файлом: настройки загрузчика сохраняются.

Откройте **Службы → Podkop config auto updater**, заполните [ссылку и токен](github-setup.ru.md), сохраните и примените. Нажмите **Тест соединения**, чтобы проверить источник, затем **Обновить сейчас**, чтобы применить конфиг. Не вставляйте токен в командную строку или адрес файла.

## Тест соединения

Начиная с 0.1.2 модули используют синтаксис экспортов, совместимый с ucode из OpenWrt 24.10 и 25.12. Если версия 0.1.1 выдаёт в SSH `Unexpected token` / `Expecting ';'`, обновите дополнение: эта ошибка возникает до скачивания конфига и не связана с токеном. Интерфейс отдельно сообщает об ошибке компиляции, отказе в доступе LuCI и ожидании ответа.

Под галочкой **Работать** выводится зелёная надпись **Программа "Podkop config auto updater" работает**, если автоматическое обновление включено в сохранённых настройках. При выключении надпись **Программа "Podkop config auto updater" выключена** имеет красноватый цвет. Статус обновляется после сохранения; он не подтверждает скачивание конфига или доступность VPN.

Кнопка использует сохранённые ссылку и токен. Во всплывающем окне отдельно отображаются скачивание файла, разбор JSON и соответствие формату конфига. Тест работает и при выключенной галочке **Работать**. Наличие несохранённых изменений самого Podkop не мешает проверке источника.

Тест не записывает конфигурацию, не перезапускает Podkop, не меняет расписание и результат последнего применения. Временные файлы удаляются после проверки. Проверяется структура скачанного файла; совместимость операций с текущими настройками роутера и доступность VPN проверкой источника не подтверждаются. При выполнении другой операции кнопка сообщает, что нужно дождаться её окончания.

Эквивалентная команда в SSH:

```sh
/usr/libexec/podkop-config-auto-updater/run test
```

Код `0`, `state: "tested"` и флаги `downloaded`, `parsed`, `valid` со значением `true` означают успех. Код `1` означает ошибку; поле `error` содержит её тип без токена и содержимого файла.

Ошибки загрузки различаются по коду curl и HTTP-ответу, без вывода тела ответа сервера, URL или токена:

| Причина | Что проверить |
| --- | --- |
| HTTP 401 | Правильность и срок действия токена |
| HTTP 403 | Права токена и ограничения GitHub API |
| HTTP 404 | Путь, ветку и доступ к файлу; приватный GitHub скрывает недоступные репозитории этим же ответом, поэтому однозначно отличить отсутствие файла от запрета доступа нельзя |
| HTTP 429 или 5xx | Повторить позднее: ограничение частоты запросов или ошибка сервера |
| DNS, соединение, таймаут | DNS роутера, маршрут и доступность сервера |
| TLS или сертификат | Дату роутера, сертификат сервера и пакет ca-bundle; проверку HTTPS отключать не нужно |
| Перенаправление или файл больше 1 МиБ | Прямую HTTPS-ссылку и размер файла |

Эти причины отображаются и при ручном тесте, и в результате применения конфига. Журнал истории не ведётся; диагностические временные файлы удаляются после операции.

## Обновление программ кнопками

**Обновить подкоп** получает последний стабильный релиз `itdoginfo/podkop` и устанавливает подходящие пакеты `podkop`, `luci-app-podkop` и русского перевода, если он уже установлен. Версии Podkop ниже 0.7.0 требуют отдельной миграции по официальной инструкции: кнопка откажется сбрасывать их конфигурацию.

Перед установкой версия самого `podkop` сравнивается с версией пакета релиза штатным `opkg compare-versions` или `apk version -t`. Если установленная версия равна доступной или новее, действие заканчивается сообщением **обновлений нет** с обеими версиями. Даже отсутствующий или отстающий LuCI не запускает установку в этом случае. Если сравнение не удалось, показывается ошибка и установка не выполняется.

**Обновить себя** получает последний стабильный релиз `hayOfLife/podkop-config-auto-updater` и устанавливает пакет этого дополнения. В обоих случаях выбирается IPK для OpenWrt 24.10 или APK для 25.12; адрес и SHA-256 пакета проверяются по сведениям официального релиза GitHub. Токен закрытого конфига для этих загрузок не используется. Более новые уже установленные пакеты не понижаются, при отсутствии обновлений установка пропускается. Для выпусков этого дополнения версия тега соответствует версии пакета с суффиксом `-r1`; при изменении `PKG_RELEASE` нужен новый номер выпуска.

Сначала сохраните или отмените ручные правки в LuCI. После нажатия установка продолжается в фоне, окно можно закрыть. Страница показывает этап и итог операции, в том числе после повторного открытия. Во время установки возможен перерыв в работе обновляемых служб. После самообновления обновите страницу браузера.

Перед установкой копии текущих конфигов Podkop и дополнения сохраняются с правами `600` в `/tmp/podkop-config-auto-updater/before-software-podkop/` или `/tmp/podkop-config-auto-updater/before-software-self/`. Здесь хранится копия перед последней попыткой установки выбранной программы. Пакетный менеджер сохраняет пользовательские настройки штатным способом; если установщик выполнил миграцию, интерфейс сообщит, что настройки изменились и их нужно проверить.

Проверка контрольной суммы выполняется до вызова пакетного менеджера. Ошибка установки или несовпадение установленной версии показывается как неуспех. Некоторые пакеты к этому моменту уже могут быть обновлены: автоматического отката программ и принудительного восстановления старой схемы настроек нет. Проверьте версии в **Система → Пакеты** и состояние Podkop перед повторной попыткой. Сохранённая копия конфигов не является резервной копией самих пакетов.

Статус можно прочитать в SSH:

```sh
/usr/libexec/podkop-config-auto-updater/software status
```

Ожидается код `0` и `state`: `idle`, `running`, `updated`, `up_to_date` или `error`. Состояние хранится в RAM и исчезает при перезагрузке роутера. Успешная установка не доказывает работу VPN-серверов. На живом роутере эти кнопки ещё не проверены.

## Расписание

Служба проверяет сохранённое расписание каждые 30 секунд. Начальная настройка выбирает минуту 0–30 ближайшего будущего ночного окна, если оно ещё не началось. После начала окна первая установка планирует следующий день.

После планового запуска выбирается новая случайная минута через заданное количество календарных дней. Перезапуск службы сохраняет назначение. Смена периода или часового пояса назначает ближайшее следующее окно. Если роутер был выключен всё окно, дневного запуска не будет: выбирается следующее ночное окно. Неудачная загрузка не стирает настройки и не вызывает цикл повторных запросов; следующий автоматический запуск состоится по расписанию, ручной доступен сразу.

Отключение **Работать** останавливает автоматическую загрузку. **Обновить сейчас** использует сохранённые поля и работает независимо от галочки. Ручное обновление не сдвигает расписание. Программа не меняет системный часовой пояс и NTP.

### Ошибка контрольной суммы при установке

Сообщение «В релизе нет единственной контрольной суммы пакета» означает, что установщик не нашёл ровно одну строку с точным именем пакета в `SHA256SUMS`. Причиной может быть отсутствующая или повторяющаяся запись, а также переносы строк CRLF. Это не сообщение о несовпадении хеша самого пакета; установка ещё не началась.

В релизе 0.1.3 причиной были CRLF; опубликованный файл исправлен 23 октября 2026 года, пакеты не изменены. Если установочный скрипт уже успешно скачан в указанный ниже путь, после исправления релиза повторите в SSH роутера от `root`:

```sh
sh /tmp/podkop-config-auto-updater-install.sh
```

Скрипт заново скачает контрольные суммы и пакет. Ожидается сообщение «Готово». Если ошибка сохраняется, не отключайте проверку SHA-256: необходимо проверить файл контрольных сумм опубликованного релиза.

## Диагностика

В SSH можно получить результат без токена и ссылок серверов:

```sh
/usr/libexec/podkop-config-auto-updater/run status
```

Код `0`, JSON со статусом и временем следующего запуска подтверждают чтение состояния. Для явного обновления:

```sh
/usr/libexec/podkop-config-auto-updater/run update
```

Код `0` и `applied` означают сохранение изменений и успешный возврат команды перезапуска Podkop; `unchanged` — отсутствие изменений. Код `1` означает ошибку, прежняя конфигурация обычно сохранена; точный результат смотрите в поле `error`. Это не доказывает доступность VPN, качество маршрутизации или завершение всех внутренних операций Podkop.

Локальные пути:

| Путь | Назначение |
| --- | --- |
| `/etc/config/podkop_config_auto_updater` | Настройки и токен, права `600` |
| `/tmp/podkop-config-auto-updater/schedule.json` | Расписание в RAM до перезагрузки, права `600` |
| `/tmp/podkop-config-auto-updater/previous-podkop` | Предыдущая конфигурация перед последним изменением, права `600` |
| `/tmp/podkop-config-auto-updater/status.json` | Последний результат; исчезает при перезагрузке |

## Отключение IPv6

Флажок **«Выключить ip v6»** по умолчанию выключен. Изменение применяется после **Сохранить и применить**, независимо от автоматического обновления. При первом включении сохраняются флаги `disable_ipv6` ядра для `all`, `default` и существующих интерфейсов. Затем IPv6 отключается, а собственный файл в `/etc/sysctl.d` закрепляет состояние после перезагрузки. Конфигурация интерфейсов `network` и DHCP не переписывается.

При снятии галочки или удалении пакета возвращается сохранённое состояние; индивидуальные настройки интерфейсов сохраняются. Если IPv6 был отключён другой программой до первого включения флажка, он останется отключённым после восстановления. Не поручайте нескольким программам одновременно менять эти sysctl-параметры.

Отключение IPv6 может оборвать текущую сессию управления через IPv6, поэтому изменяйте флажок через IPv4-адрес роутера. Снимок находится в `/etc/podkop-config-auto-updater/ipv6-restore`. При ошибке применения интерфейс покажет сообщение, а системный журнал — запись с именем программы. Это управление стеком IPv6 роутера; оно не заменяет отдельную настройку IPv6 на клиентах локальной сети.

## Восстановление

Если команда перезапуска вернула ошибку, загрузчик возвращает прежний файл и снова вызывает перезапуск. Если за это время настройки изменились вручную, автоматический откат не выполняется. Резервная копия содержит учётные данные серверов.

Для ручного восстановления сначала выключите **Работать** и сохраните настройку. Убедитесь, что никто не редактирует Podkop и операция обновления закончилась. Затем выполните:

```sh
cp /etc/config/podkop /tmp/podkop-config-auto-updater/before-manual-restore
cp /tmp/podkop-config-auto-updater/previous-podkop /etc/config/podkop
chmod 600 /etc/config/podkop /tmp/podkop-config-auto-updater/before-manual-restore
/etc/init.d/podkop restart
```

Команды заменяют конфигурацию Podkop предыдущей. Ожидается код `0` у перезапуска; проверьте настройки в LuCI. Чтобы вернуть состояние до ручного восстановления, скопируйте `before-manual-restore` обратно в `/etc/config/podkop` и перезапустите Podkop. Не повторяйте восстановление вслепую при ошибке диска или отсутствующей резервной копии.

## Удаление

Выполните для вашего пакетного менеджера:

```sh
/etc/init.d/podkop_config_auto_updater stop
/etc/init.d/podkop_config_auto_updater disable
opkg remove luci-app-podkop-config-auto-updater
```

На OpenWrt 25.12 последняя команда — `apk del luci-app-podkop-config-auto-updater`. Ожидается код `0`. Конфигурация Podkop остаётся; каталог `/etc/podkop-config-auto-updater` и настройки загрузчика могут сохраняться. Отзовите ненужный токен на GitHub. Для возвращения программы установите пакет заново.

С версии 0.1.4 расписание, время последнего обновления, статусы, скачанные файлы и автоматические резервные копии хранятся в RAM (`/tmp/podkop-config-auto-updater`) и исчезают после перезагрузки роутера. После перезагрузки выбирается новое ближайшее ночное окно. На флеш-памяти остаются настройки UCI с токеном, применённый конфиг Podkop и данные восстановления IPv6. Старые копии в `/etc/podkop-config-auto-updater` автоматически не удаляются.
