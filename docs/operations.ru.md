# Установка и обслуживание

Инструкция для администратора OpenWrt. Команды выполняются в SSH роутера от `root`, оболочка `/bin/sh`, рабочий каталог `/tmp`. Перед установкой сохраните резервную копию через LuCI. Нужны установленный Podkop, точные часы, HTTPS-доступ к источнику и свободное место для зависимостей.

## Установка и обновление

Рекомендуемый путь — установочный скрипт. В SSH роутера, от `root`, из `/tmp` выполните:

```sh
uclient-fetch -O /tmp/podkop-config-auto-updater-install.sh https://raw.githubusercontent.com/hayOfLife/podkop-config-auto-updater/main/install.sh
sh /tmp/podkop-config-auto-updater-install.sh
```

Скрипт поддерживает только стабильные ветки 24.10 и 25.12, требует уже установленный Podkop, `jsonfilter`, `sha256sum` и HTTPS-загрузчик. Он получает последний опубликованный релиз, выбирает подходящий IPK/APK, сверяет SHA-256, обновляет индекс пакетов и устанавливает только приложение с его зависимостями. Он не прошивает роутер и не выполняет массовое обновление пакетов. Если в релизе нет нужного файла или сумма не совпадает, установка не начинается.

Ожидается код `0` и сообщение «Готово». Повторный запуск обновляет программу, сохраняя её настройки; копия существующего конфига загрузчика сохраняется в `/etc/podkop-config-auto-updater/before-install-config`. Если опубликованного релиза пока нет, скрипт сообщит об ошибке получения релиза. Удаление и восстановление описаны в соответствующих разделах этой инструкции.

Для ручной установки используйте следующий путь.

Скачайте артефакт успешной сборки из [GitHub Actions](https://github.com/hayOfLife/podkop-config-auto-updater/actions), распакуйте ZIP на компьютере и загрузите пакет на роутер в `/tmp`. Используйте IPK только на OpenWrt 24.10, APK только на 25.12. Имя файла ниже соответствует версии 0.1.0, release 1; сверяйте его с артефактом сборки.

Для OpenWrt 24.10:

```sh
opkg update
opkg install /tmp/luci-app-podkop-config-auto-updater-openwrt-24.10.ipk
```

Для OpenWrt 25.12:

```sh
apk update
apk add --allow-untrusted /tmp/luci-app-podkop-config-auto-updater-openwrt-25.12.apk
```

Ожидается код `0` и установленный `luci-app-podkop-config-auto-updater`. `--allow-untrusted` требуется для локального пакета без доверенного ключа подписи; не отключайте проверку TLS. Зависимости устанавливаются из настроенных репозиториев OpenWrt. Эти команды меняют состав пакетов, но не обновляют всё окружение. Для обновления повторите установку с новым файлом: настройки загрузчика сохраняются.

Откройте **Службы → Podkop config auto updater**, заполните [ссылку и токен](github-setup.ru.md), сохраните и примените. Затем нажмите **Обновить сейчас**. Не вставляйте токен в командную строку или адрес файла.

## Расписание

Служба проверяет сохранённое расписание каждые 30 секунд. Начальная настройка выбирает минуту 0–30 ближайшего будущего ночного окна, если оно ещё не началось. После начала окна первая установка планирует следующий день.

После планового запуска выбирается новая случайная минута через заданное количество календарных дней. Перезапуск службы сохраняет назначение. Смена периода или часового пояса назначает ближайшее следующее окно. Если роутер был выключен всё окно, дневного запуска не будет: выбирается следующее ночное окно. Неудачная загрузка не стирает настройки и не вызывает цикл повторных запросов; следующий автоматический запуск состоится по расписанию, ручной доступен сразу.

Отключение **Работать** останавливает автоматическую загрузку. **Обновить сейчас** использует сохранённые поля и работает независимо от галочки. Ручное обновление не сдвигает расписание. Программа не меняет системный часовой пояс и NTP.

## Диагностика

В SSH можно получить результат без токена и ссылок серверов:

```sh
/usr/libexec/podkop-config-auto-updater/run status
```

Код `0`, JSON со статусом и временем следующего запуска подтверждают чтение состояния. Для явного обновления:

```sh
/usr/libexec/podkop-config-auto-updater/run update
```

Код `0` и `applied` означают сохранение изменений и успешный возврат команды перезапуска Podkop; `unchanged` — отсутствие изменений. Код `1` означает ошибку, прежняя конфигурация обычно сохранена; точный результат смотрите в поле `error`. Это не доказывает доступность VPN, качество маршрутизации или завершение всех внутренних операций Podkop.

Локальные пути:

| Путь | Назначение |
| --- | --- |
| `/etc/config/podkop_config_auto_updater` | Настройки и токен, права `600` |
| `/etc/podkop-config-auto-updater/schedule.json` | Постоянное расписание, права `600` |
| `/etc/podkop-config-auto-updater/previous-podkop` | Предыдущая конфигурация перед последним изменением, права `600` |
| `/tmp/podkop-config-auto-updater/status.json` | Последний результат; исчезает при перезагрузке |

## Отключение IPv6

Флажок **«Выключить ip v6»** по умолчанию выключен. Изменение применяется после **Сохранить и применить**, независимо от автоматического обновления. При первом включении сохраняются флаги `disable_ipv6` ядра для `all`, `default` и существующих интерфейсов. Затем IPv6 отключается, а собственный файл в `/etc/sysctl.d` закрепляет состояние после перезагрузки. Конфигурация интерфейсов `network` и DHCP не переписывается.

При снятии галочки или удалении пакета возвращается сохранённое состояние; индивидуальные настройки интерфейсов сохраняются. Если IPv6 был отключён другой программой до первого включения флажка, он останется отключённым после восстановления. Не поручайте нескольким программам одновременно менять эти sysctl-параметры.

Отключение IPv6 может оборвать текущую сессию управления через IPv6, поэтому изменяйте флажок через IPv4-адрес роутера. Снимок находится в `/etc/podkop-config-auto-updater/ipv6-restore`. При ошибке применения интерфейс покажет сообщение, а системный журнал — запись с именем программы. Это управление стеком IPv6 роутера; оно не заменяет отдельную настройку IPv6 на клиентах локальной сети.

## Восстановление

Если команда перезапуска вернула ошибку, загрузчик возвращает прежний файл и снова вызывает перезапуск. Если за это время настройки изменились вручную, автоматический откат не выполняется. Резервная копия содержит учётные данные серверов.

Для ручного восстановления сначала выключите **Работать** и сохраните настройку. Убедитесь, что никто не редактирует Podkop и операция обновления закончилась. Затем выполните:

```sh
cp /etc/config/podkop /etc/podkop-config-auto-updater/before-manual-restore
cp /etc/podkop-config-auto-updater/previous-podkop /etc/config/podkop
chmod 600 /etc/config/podkop /etc/podkop-config-auto-updater/before-manual-restore
/etc/init.d/podkop restart
```

Команды заменяют конфигурацию Podkop предыдущей. Ожидается код `0` у перезапуска; проверьте настройки в LuCI. Чтобы вернуть состояние до ручного восстановления, скопируйте `before-manual-restore` обратно в `/etc/config/podkop` и перезапустите Podkop. Не повторяйте восстановление вслепую при ошибке диска или отсутствующей резервной копии.

## Удаление

Выполните для вашего пакетного менеджера:

```sh
/etc/init.d/podkop_config_auto_updater stop
/etc/init.d/podkop_config_auto_updater disable
opkg remove luci-app-podkop-config-auto-updater
```

На OpenWrt 25.12 последняя команда — `apk del luci-app-podkop-config-auto-updater`. Ожидается код `0`. Конфигурация Podkop остаётся; каталог `/etc/podkop-config-auto-updater` и настройки загрузчика могут сохраняться. Отзовите ненужный токен на GitHub. Для возвращения программы установите пакет заново.
